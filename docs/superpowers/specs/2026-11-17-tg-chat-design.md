# 面板聊天页改成 Telegram 桌面版的样子

日期：2026-11-17
状态：部署者确认"开工"，认可了草图，包括"顶部导航收进 ≡ 菜单"和"列表每行标题用角色名"。标"实施者决定"的条目由我决定，部署者可以事后改。

## 1. 为什么

部署者想让面板里的聊天页用起来像 Telegram 桌面版，并给了截图作为参照。这个改动只针对聊天页（`#/chat`、`#/chat/<key>`），其他页面不动。

## 2. 布局（占满整个浏览器窗口）

进入聊天页后，隐藏面板顶部的导航栏，聊天页占满整个视口。离开聊天页时恢复导航栏。

页面从左到右分三栏：

**1. 文件夹栏**（窄，约 72px）

- 最上面是 ≡ 按钮，点开是一个菜单，包含：
  - 面板其他页面的链接：概览、用量、会话、人设模板、任务、审计、配置；
  - 新建 Bot；
  - 当前用户名和"退出"。
- ≡ 下面依次是：
  - "全部"；
  - 每个 bot 一项。图标用 bot 的头像（见第 4 节），下面是 bot 名，名字太长时截断。

  当前选中的那一项高亮。选中状态记在网址里：`#/chat?bot=<id>`，带着聊天时是 `#/chat/<key>?bot=<id>`。这个写法是实施者决定，前提是路由能带查询参数；不能的话改存 `sessionStorage`。

**2. 聊天列表**（约 320px）

- 顶部是搜索框，按角色名或预览文字筛选。
- 选中某个 bot 时，搜索框下方显示一行：bot 名，以及"编辑""删除"两个按钮（"删除"只对面板 bot 显示）。这两个按钮沿用现有的对话框。
- 每行包括：
  - 圆形头像；
  - 角色名（加粗）；
  - 右上角是时间：当天显示"时:分"，今年内显示"月-日"，更早的显示"年-月-日"；
  - 第二行是最后一条消息的预览，单行，超出部分显示省略号。最后一条是你发的时，前面加"你："；
  - 右下角是未读数的圆形徽章（见第 5 节）。

  当前打开的聊天高亮。
- 列表右下角有一个圆形浮动按钮"✎"，点了打开现有的"新建聊天"对话框。选中某个 bot 时，对话框里默认选这个 bot。
- 列表为空时显示"还没有聊天，点右下角的 ✎ 开始"。

**3. 对话区**

- 没有选中聊天时，正中显示一个圆角小标签"选择一个对话开始聊天"。
- 选中后，从上到下依次是：
  - **顶栏**：头像、角色名，名字下面一行显示"正在输入…"。这一行在 `GET …/chat` 返回 `typing` 时显示，否则空着（实施者决定：不显示"在线"）。顶栏右边是 ⋮ 菜单，包含：
    - 会话详情；
    - 建议回复的开关，替代现在输入框下面的复选框；
    - 删除这个聊天，沿用现有的删除确认。
  - **消息区**：见第 3 节。
  - **建议回复**：做成 Telegram 机器人内联按钮的样子，见第 3 节。
  - **输入栏**：圆角输入框，高度随内容自动增加，最多 6 行。右边是圆形发送按钮"➤"。回车发送，Shift+回车换行，这和现在一样。

**窄屏**（宽度不到 700px）：像 Telegram 手机版那样单栏切换。

- 没打开聊天时，只显示文件夹栏和列表。此时文件夹栏变成列表上方一排横向滚动的标签（实施者决定）。
- 打开聊天时，只显示对话区，顶栏左边有"←"返回按钮。

## 3. 消息样式

- **气泡**：你发的消息靠右，用强调色（蓝色）气泡，白字；角色的消息靠左，用深色气泡。
  - 时间放在气泡右下角，小字，格式"时:分"。
  - 去掉每条消息上的"面板"标签。只有渠道不是 `panel` 的消息才显示渠道标签，保持现在的含义。
  - 被审查拦下的提示，也就是现有的 `suppressed` 提示，保持不变。
- **分组**：同一方连续发的消息，间距缩小，只有最后一条带气泡尾巴。气泡尾巴用 CSS 实现。
- **日期分隔线**：跨天的地方显示居中的圆角小标签，文字为"11月17日"；如果不是今年，显示"2025年11月17日"。
- **建议回复**：贴在最后一条角色消息下方，每条一个按钮，按钮占满一行宽，圆角，半透明，像 Telegram 的内联键盘。点按钮和现在一样，直接发送。
- **滚动**：沿用现有逻辑。新消息到达时，如果你在底部，就自动滚到底；向上翻页加载历史的行为不变。

## 4. 头像

- bot 的头像取它私聊默认模板的参考图。图片通过已有的 `api/persona-images/<id>?size=reply` 读取，用 CSS 的 `object-fit: cover` 裁成圆形。
- 没有参考图时，显示彩色圆底加名字的第一个字。颜色由 bot ID 的哈希决定，从 8 种固定颜色里选（实施者决定）。
- 你发的消息不显示头像，Telegram 私聊也是这样。

## 5. 未读

- 按浏览器记录：`localStorage` 里存"每个聊天看过时的消息总数"。
- 未读数 = 当前消息总数 − 看过时的总数；如果小于 0，按 0 算，并把记录重置为当前总数。
- 打开一个聊天，或者它正在显示时有新消息到达，都把"看过时的总数"更新为最新值。
- 从来没打开过的聊天，第一次加载列表时把当时的总数记为"看过"，避免一上来全是未读（实施者决定）。

## 6. 接口改动

`GET /panel/api/chats`：

- 每个 bot 增加 `avatar`，即参考图 ID，没有时为 `""`。
- 每个聊天增加：
  - `message_count`；
  - `last`，没有消息时为 `null`。格式为 `{"seq":…, "from_bot":bool, "at":"RFC3339", "text":"…"}`。其中 `text` 合成一行，最多 60 字，超出时末尾加"…"（实施者决定）。

存储层新增 `LastMessages(ctx, keys []string) (map[string]store.MessageRecord, error)`，一次查询取出每个会话 `seq` 最大的那条消息。

## 7. 不做

- 不改其他页面的样式。
- 不做服务端已读状态，不做多设备同步。
- 不做表情、图片和文件发送。
- 不做消息右键菜单。
- 不改轮询频率和接口语义，只加字段。

## 8. 方案

- **A（选定）**：在现有的原生 JS 视图上重写聊天页的布局和样式，接口只加字段。不引入任何前端框架或依赖。
- **B（没采用）**：引入前端框架，或者复制一套 Telegram 的 Web 前端。项目目前没有前端构建流程，增加依赖违反项目惯例。
