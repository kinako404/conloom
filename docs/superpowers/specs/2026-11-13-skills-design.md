# Skill（技能）框架设计

日期：2026-11-13
状态：已定稿，待实施
上位文档：总设计 §9（Tool Gateway）

## 1. 为什么做

- 现在机器人的能力都靠用户手打命令触发：`/记住`、`/记忆`、`/好感度`。用户说"记住我喜欢草莓"时，模型只能嘴上答应，实际什么都没记。
- 私聊记忆的短板是"回忆"：注入的只有摘要和笔记，问到更早的具体事情时，模型就会编。
- 实测（2026-11-13）：短模型 qwen3.8-27b（开启思考）和长模型 deepseek-v4-pro 都支持 OpenAI 标准的工具调用。四个测试用例全部判断正确：记住、回忆、闲聊不调用、查好感度。每次多 1–2 秒。

## 2. 目标、非目标、反目标

**目标**

1. 通用的技能框架。技能就是一个目录里的 `SKILL.md`：开头写元数据，正文写给模型的用法说明。每个技能用到一个或多个内置工具。
2. 内置技能打包进二进制；可以在 `skills.dir` 目录里新增技能，或按名字覆盖内置技能的说明。每个机器人用 `bots[].skills` 选择启用哪些技能。
3. 执行器支持工具调用循环：模型发起调用 → 执行 → 把结果交回模型 → 模型继续，直到给出最终回复。
4. 第一批内置技能：
   - `memory`，包含工具 `remember`、`recall`、`get_affinity`；
   - `time`，包含工具 `now`。

**非目标（v1 不做）**

- HTTP 等外部工具类型，比如搜索、ComfyUI。格式里预留了扩展的位置，v2 再做。
- 在聊轮次、主动加入、会话外提问中使用工具。v1 只在**私聊**和**群里的直接对话**（@ 或回复机器人）中启用。
- 渐进式加载（按需读取技能正文）。v1 技能少，正文直接放进 system。
- 删除数据、改设置这类操作（`/忘记我`、`/persona use`、`/pause` 等），这些继续只能用命令。

**反目标**

- 工具替别人做事：任何工具都只作用于当前说话的人和当前会话，参数里不允许出现用户 ID 或会话 ID。
- 工具结果泄露别的会话的内容、QQ 号或用户 ID，或者被忘记的内容。
- 模型在回复里暴露工具名、"系统"、JSON 之类的痕迹。
- 工具失败导致回复失败：工具出错只告诉模型，对话照常进行。
- 无限循环：调用轮数和次数都有上限。

## 3. 方案取舍

| 方案 | 结论 |
|---|---|
| **OpenAI 标准 tools / tool_calls（选用）** | 两个模型实测都支持，格式标准，以后换模型也不受影响 |
| 让模型输出自定义标记，比如 `[[REMEMBER:…]]` | 不需要协议支持，但容易出格式错误、和正文混在一起，也拿不到参数结构，不用 |
| Anthropic 式渐进加载：先只给描述，模型再用 `use_skill` 读正文 | 技能多的时候省 token，但每次多一轮调用；v1 技能少，先直接放进 system，以后技能多了再加 |

## 4. 设计

### 4.1 技能文件

```markdown
---
name: memory
description: 记住用户要求记住的事、回忆以前聊过的内容、查询好感度
tools: [remember, recall, get_affinity]
conversations: [private, group]
---
（给模型看的用法说明，不超过 600 字）
```

- 内置技能放在 `internal/skills/builtin/<name>/SKILL.md`，用 go:embed 打包进二进制。
- `skills.dir` 可选，相对路径按配置文件所在目录解析。目录里每个 `<name>/SKILL.md`：
  - name 与内置技能相同时，替换内置技能；
  - name 不同时，作为新技能加入。
  
  v1 的技能只能引用内置工具。
- 启动时校验：frontmatter 必须完整；引用的工具必须存在；conversations 只能取 private 或 group；正文不超过 600 字。校验失败按配置错误处理，退出码 78。
- `bots[].skills: [memory, time]`：要启用的技能名列表。省略或为空时不启用任何工具，行为和现在完全一样。

### 4.2 内置技能

**memory 的正文（原样使用）：**

```
- 用户明确让你记住一件关于他自己的事时，调用 remember。联系方式、证件号、别人的隐私不要记。
- 用户问到以前聊过、但眼前的对话和你记得的事里都没有的内容时，先调用 recall 查一查，再回答；查不到就老实说不记得，不要编。
- 用户问你对他的好感、你们有多熟时，调用 get_affinity。
- 调用之后，用你自己的口吻自然地回复，不要提到工具、系统或查询过程。
```

**time 的正文（原样使用）：**

```
- 用户问今天几号、星期几、现在几点，或者回答需要知道"今天"时，调用 now。
- 用你自己的口吻自然地说出来，不要照抄格式。
```

### 4.3 内置工具（`internal/skills/tools`）

所有工具都实现 `skills.Tool` 接口（见 `internal/skills/skill.go`）。它们只能通过 `Invocation` 拿到"是谁、在哪个会话"，**参数里没有任何身份信息**。

| 工具 | 参数 | 行为 | 返回给模型的文本 |
|---|---|---|---|
| `remember` | `content`：字符串，1–100 字 | 和 `/记住` 完全相同：先审查，拒绝联系方式和证件号，再追加"（他让我记住）…"，必要时裁剪，并写 revision。记忆未生效时不写。把 `/记住` 的实现挪进 internal/memory，命令和工具共用 | `已记住。`，或者用一句话说明拒绝原因（不能记这类信息、记忆没有开启、内容为空或太长） |
| `recall` | `query`：字符串，1–100 字 | 在**本会话**最近 5000 条消息里按关键词查找：汉字按相邻两个字切词，英文和数字按单词切词，最多 8 个词，按命中词数排序。取前 6 条，每条带前后各 2 条上下文，相邻的合并。私聊里，忘记时间之前的消息都不查；群聊里，被忘记的人在忘记时间之前的消息不查。按时间顺序排列 | 每行 `[MM-DD HH:MM] 名字：正文`。机器人自己的消息写成"你"，没有名字时写"一位群友"，不出现任何 ID。总长不超过 1500 字。找不到时返回 `没有找到相关的聊天记录。` |
| `get_affinity` | 无 | 读取说话人的好感度 | `好感：熟悉（52/100）`；没有好感度时返回 `你们还不太熟，还没有好感度。`；记忆没有生效时返回 `这个会话没有开启记忆。` |
| `now` | 无 | 按 `server.timezone` 取当前时间 | `2026-11-13 星期五 16:30（Asia/Shanghai）` |

### 4.4 工具调用循环（`internal/core/runner.go`）

- **启用条件**：机器人启用了技能，会话类型在技能的 `conversations` 里，并且任务是私聊或群里的直接对话（addressed）。其他任务不带 tools，行为和现在一样。
- **system 末尾追加技能段**：
  ```
  【技能】你可以在需要时调用下面的工具；不需要时直接回复。
  <每个启用技能的正文>
  ```
  对同一个机器人、同一个会话类型来说，这一段是固定的，不影响 system 前缀的稳定。工具定义和技能段都计入 BaseTokens。
- **循环**：
  1. 带 tools 调用模型。
  2. 返回 tool_calls 时，按顺序执行，每轮最多 4 个，超出的回复"本轮调用太多"。把带 tool_calls 的 assistant 消息和每个调用的 tool 消息追加到对话里，再调用一次。
  3. 最多 3 轮。第 3 轮之后还要调用工具时，最后一次请求不带 tools（或者设 `tool_choice: none`），强制模型给出文字回复。
  4. 未知的工具名、参数不是合法 JSON、工具返回 error 时，tool 消息写 `调用失败。`，不带细节，模型继续。
  5. 单个工具结果截断到 2000 字。
- **路由和准入**：每轮都重新申请准入；整个循环用同一个模型配置，失败时沿用现有的重路由逻辑。
- **最终文本**：走现有的输出处理，包括 SKIP、去掉照抄的记录格式、审查、发送。中间轮次模型给出的 content 不发送。
- **记录**：任务结束时汇总每个工具的调用次数。

### 4.5 模型调用层（`internal/provider/openai`）

- `ChatRequest` 新增 `Tools` 和 `ToolChoice`。
- `ChatMessage` 支持 assistant 消息的 `tool_calls`（此时 content 可以为空）和 tool 消息的 `tool_call_id`。
- `ChatResponse` 新增 `ToolCalls`。
- 原有清理逻辑（去掉 think 段等）只作用于 content。

### 4.6 可观测性

- 指标：`conloom_skill_calls_total{tool, result="ok|error|unknown|invalid"}`。
- 日志：每次调用打一条 Info `skill call`，带 task_id、tool、duration_ms、ok。**不记录参数和结果的内容。**

### 4.7 配置示例

```yaml
skills:
  dir: ./skills     # 可选
bots:
  - id: bot_tg
    skills: [memory, time]
```

## 5. 我做的决定（可以推翻）

- v1 只做内置工具，HTTP 工具放到 v2。
- 工具只在私聊和直接对话中启用。
- 技能正文直接放进 system，不做渐进加载。
- 删除类和管理类操作继续只用命令。
- `recall` 用关键词扫描最近 5000 条消息，不建全文索引。消息量大了再换 FTS。
- 线上先只给 Telegram 机器人启用 `memory` 和 `time`，QQ 机器人以后再说。

## 6. 测试要点

- **模型调用层**：tools 能正确序列化；tool_calls 能正确解析；assistant 消息带 tool_calls 时 content 可以为空；tool_call_id 能往返。
- **循环**：
  - 单轮调用、多轮调用、超过轮数后强制给出文字；
  - 每轮超过 4 个调用；
  - 未知工具、坏 JSON、工具报错时，对话继续；
  - 中间轮次的 content 不发送；
  - 非直接对话、未启用技能时不带 tools，行为和现在逐字节一致。
- **工具**：
  - remember 和 `/记住` 行为一致；
  - recall 的分词、排序、上下文合并、长度上限，以及会话隔离和忘记过滤；结果里没有 ID；
  - get_affinity 的三种返回；
  - now 的时区和格式。
- **加载**：内置技能能加载；`skills.dir` 能覆盖和新增；frontmatter 不完整、引用的工具不存在、正文超长时报错。
- **e2e**：假模型先返回 tool_calls、再返回文本，跑通"记住草莓 → 记忆里有这一条 → 回复里没有工具痕迹"。
