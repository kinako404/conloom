# 面板"设置"页：默认策略搬进数据库

日期：2026-11-18
状态：部署者确认"开工"，范围是第一期只放两段默认策略。标"实施者决定"的条目由我决定，部署者可以事后改。

## 1. 为什么

配置文件里的 `default_group_policy`（群聊默认策略）和 `default_private_policy`（私聊默认策略）决定每个会话的默认行为，比如分几条发、多久回、主动搭话、免打扰、记忆整理和审查。现在改它们要 SSH 上去改文件再重启，面板的"配置"页只能看。部署者要求在面板里新增"设置"页来改这些系统通用配置。

## 2. 目标、非目标、反目标

**目标**

1. 两段默认策略存进数据库，有版本、审计，可以回滚。
2. 面板新增顶层"设置"页可以修改；保存后立即生效，不用重启。
3. 第一次启动时把配置文件里的值导入数据库；导入之后配置文件里再出现这两段，启动报错（退出码 78）。
4. 会话的"策略"页新增"改回跟随默认"。

**非目标（第一期不做）**

- 其他配置段不搬，包括时区、语义检索、日志级别、运行参数、模型、令牌、适配器、面板登录。
- 公开 REST API（`/api/v1`）不提供修改默认策略的接口，只有面板能改。

**反目标（出现就算失败）**

- 改了默认值后，跟随默认的会话还在用旧值，比如暂停、主动搭话的计划、记忆开关没有跟着变。
- 改坏了默认值导致服务起不来。保存时必须用和配置文件相同的规则校验。
- 已经单独存过策略的会话被默认值的改动覆盖。

## 3. 存储

新增迁移 `0021`：

- **新表 `policy_defaults`**：列为 `kind`（`group`/`private`）、`version`、`policy`（JSON）、`reason`、`updated_by`、`created_at`，主键 `(kind, version)`。每次修改追加一个新版本，和 `group_policies` 的做法一样。
- **`group_policies` 加一列 `follows_defaults INTEGER NOT NULL DEFAULT 0`**：最新版本带这个标记时，表示"这个会话改回跟随默认"。策略解析时当作没有单独存过策略处理。历史版本保留，版本号继续递增，审计里引用的版本号仍然对得上。

## 4. 启动与导入（照 bot 设置迁移的做法）

**配置解析**：两段改为可选的"旧键"，即指针字段，`nil` 表示文件里没有这一段。旧键只在导入前按原来的规则校验，包括 `Validate` 和上下文上限检查；这样适配器读同一个文件时仍然能正常解析。

**启动时按下面四种情况处理**：

| 数据库里已有默认策略 | 配置文件里有这两段 | 处理 |
|---|---|---|
| 没有 | 有 | 在一个事务里导入为版本 1，`updated_by=system`，原因是"从配置文件导入"；记 app_meta 键 `config_policy_defaults_migrated` 和审计 `settings.policy.migrate`；日志警告"请从配置文件删掉这两段"。 |
| 没有 | 没有 | 写入内置默认值作为版本 1：群聊用 `conloomapi.DefaultGroupPolicy()`，私聊沿用现在的回退规则（等于群聊默认，但摘要、笔记字数上限为 0）。不记 meta。 |
| 有 | 有 | 启动报错，退出码 78。中文错误写明导入时间，以及要删掉哪两段。 |
| 有 | 没有 | 正常使用数据库里的值。 |

两段可以分开判断（实施者决定）：比如文件里只有群聊这段时，私聊默认按"都没有"的规则写内置值。

**一处语义变化**：私聊默认策略不再在缺省时从群聊默认"回退"，两段在数据库里各自独立。文档要写明这一点。

## 5. 运行时

- `policy.Service` 的默认值改为从数据库读，提供 `SetDefaults(kind, policy)`。它在锁内替换默认值，清空所有会话的策略缓存（缓存里已经合并了默认值）。
- **改默认值后要通知受影响的会话**，也就是这一类会话里跟随默认的（没有单独存策略，或最新版本带 `follows_defaults`）。对每个这样的会话，执行和"它自己的策略改了"一样的后续处理：
  - 暂停或恢复，以及取消排队；
  - 重新唤醒调度；
  - 私聊重新安排主动找人；
  - 记忆调度器在记忆刚打开时开始整理。

  现在记忆调度器是靠比较版本号来判断"记忆刚打开"的，改默认值这条路径要改成直接比较改前、改后的生效策略。会话很多时分批处理，不能卡住保存请求，可以先返回、后台慢慢做（实施者决定）。
- **校验**：保存默认值时，用和会话策略相同的校验，包括 `Validate` 和上下文上限检查（`Service.reserved`）。
- **启动时的警告也在保存时检查一遍**：审查级别、输出预留、私聊记忆的敏感内容设置。检查结果作为 `warnings` 返回给面板显示，同时写日志。
- **"改回跟随默认"**：给这个会话追加一个带 `follows_defaults` 的版本。之后它和没存过策略的会话一样跟随默认值，并按上一条触发一次"它自己的策略改了"的后续处理。如果这个会话当前是暂停状态，改回之后会按默认值取消暂停，确认框要写明这一点。

## 6. 面板

**接口**：都是面板的写接口，带会话鉴权和 CSRF。

- `GET /panel/api/settings/policies` 返回群聊、私聊两段，每段包括：
  - `current`：版本、策略、原因、修改人、时间；
  - `versions`：最多 50 个；
  - `followers`：当前跟随默认的会话数；
  - `memory_limits`：同会话策略页。
- `PUT /panel/api/settings/policies/{kind}`，请求体 `{policy, reason}`，生成新版本，返回 200 和 `{current, warnings}`。校验失败返回 400，错误信息带字段路径。
- `POST /panel/api/settings/policies/{kind}/restore`，请求体 `{version, reason}`，把旧版本复制成一个新版本。
- `POST /panel/api/conversations/{key}/policy/follow-defaults`，请求体 `{reason}`，返回 200 和更新后的策略视图。
- 审计：
  - 修改和恢复默认策略记 `settings.policy.update`，内容是 `{kind, version, action: update|restore}`；
  - 改回跟随默认记 `policy.update`，`action` 为 `follow_defaults`；
  - 导入记 `settings.policy.migrate`。

**导航**：新增顶层"设置"，路由 `#/settings`，放在"配置"前面。顺序是：概览、用量、聊天、会话、人设模板、任务、审计、设置、配置。TG 页 ≡ 菜单里的列表也跟着变，因为它和顶部导航共用同一份列表。

**设置页的布局**：群聊、私聊两块，每块包括：

- **常用项表单**：字段和会话"策略"页的常用项相同，包括主动开关、记忆开关、摘要和笔记字数、历史条数、分条上限；私聊块另外有等待时间、主动档位和免打扰时段。表单要抽成共用模块 `views/policyform.js`，会话页和设置页都用它，不复制代码。
- **"高级"折叠区**：完整策略的 JSON 编辑器，做法和会话页现有的相同。
- **原因输入框和保存按钮**。保存成功后显示 `warnings`。
- **版本列表**：每个版本有"恢复此版本"。
- 每块顶部写一句"当前有 N 个会话跟随这个默认值；单独改过策略的会话不受影响。"

**会话"策略"页**：

- 明确显示两种状态之一："跟随默认（群聊/私聊默认 第 N 版）"，或"单独设置（第 N 版）"。
- 单独设置时，显示"改回跟随默认"按钮，带确认框。如果当前是暂停状态，确认框要提示改回后会取消暂停。

**"配置"页**：两段默认策略改为显示数据库里的值，标注 `source: panel`，并提示"在设置页修改"；页面原有的"改文件后重启"提示，排除这两段。

## 7. 文档和示例配置

- `conloom.example.yaml`：删掉这两段，在原来的位置留注释"已搬到面板的设置页；旧文件第一次启动时会自动导入，之后要删掉这两段"。
- `docs/configuration.md`：策略各字段的说明保留，改为"在面板设置页修改"；写清导入规则、"私聊不再回退到群聊"、退出码 78。

## 8. 部署时（不进仓库）

1. 备份数据库和配置文件。
2. 第一次启动：导入，迁移版本升到 21。
3. 核对：设置页显示的值和原配置一致，比如私聊 `max_parts=5`。
4. 用精确脚本从线上配置里删掉这两段，校验配置后重启，确认没有警告。
5. 实测：在设置页改一个值，跟随默认的会话立即生效；再改回原值。

## 9. 方案

- **A（选定）**：默认策略作为数据库里的版本化数据，导入规则和 bot 设置迁移一致，运行时热替换并通知跟随默认的会话。
- **B（没采用）**：在面板里直接改写 YAML 文件，再热重载。会动到有密钥的文件，也不好做版本和审计；适配器进程也读这个文件，并发写有风险。
- **C（没采用）**：配置文件和数据库并存，数据库优先。两处都有值容易让人困惑，和 bot 设置的先例也不一致。
