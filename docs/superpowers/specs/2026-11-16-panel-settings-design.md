# 人设性别、模板与 bot 解绑、平台 bot 设置挪到面板、面板建议回复

日期：2026-11-16
状态：已定稿，部署者确认"开工"。标"实施者决定"的条目由我决定，部署者可以事后改。

## 1. 人设性别和关系词方向

复测时，qwen 会把男女关系词说反。两个例子：

- 女性角色说"再让它叫我一声老公"；
- 把"博士"说成"女朋友"。

原因是人设里没有性别信息，提示词里也没要求模型分清关系词的方向。

改动：

- `PersonaDoc` 新增 `gender` 字段，取值 `female`、`male` 或空。
  - 有值时，`Render` 在"角色设定"之后、"外貌"之前写一行：`性别：女。` 或 `性别：男。`
  - 为空时，渲染结果和现在逐字节相同。
- 基础提示（`CorePrompt`）末尾加一句：

  > 说到恋人、夫妻、亲属这类关系时，分清自己是哪一方、对方是哪一方，称呼和关系词不要说反：女性一方是女朋友、妻子、老婆，男性一方是男朋友、丈夫、老公。

  所有会话的系统提示都会因此改变一次，系统提示缓存随之失效，属于预期行为。
- 面板的人设表单新增"性别"下拉框，选项为：不指定、女、男。
- 部署时，把线上三个角色模板的性别设为"女"。

## 2. 模板与 bot 解绑

- 模板列表去掉"默认模板用于"一列。
- 新增"新建模板"按钮，弹窗里填两项：
  - 模板名（沿用现有规则）；
  - 起点：空白（即内置默认人设）或复制某个已有模板。

  "复制为新模板"按钮保留。
- 删除不再拦着：任何模板都能删，`default` 除外，因为它是内置兜底。
  - 删掉一个正被 bot 用作默认的模板后，那个 bot 改用 `default`。
  - 面板上那个 bot 显示"人设模板 X 已不存在，暂用 default"，复用现有的问题标注机制。
  - 删除前的确认提示要写明有哪些 bot 在用这个模板。
  - 接口不再返回 409 `TEMPLATE_IN_USE`，改为删除成功，响应里列出受影响的 bot。

## 3. 平台 bot（QQ、Telegram）的设置挪到面板

**留在配置文件里**：

- `bots[]` 的 `id`、`platform`、`platform_self_id`；
- 连接和密钥：适配器配置、令牌、`.env`。

**挪到面板，存进数据库**：

- 显示名 `name`；
- 管理员列表 `admins`；
- 私聊开放范围 `private_chat`（off、admins、allowlist、all）；
- 私聊白名单；
- 启用的群列表；
- **首次私聊用的默认模板**；
- **拉进群时用的默认模板**；
- 技能 `skills`。

**存储**：迁移 `0019_bot_settings.sql`，按 bot ID 存一行，列表类字段存 JSON。

**一次性迁移**：

- 启动时，如果某个配置 bot 在数据库里还没有设置行，就用配置文件里的值生成一行：
  - 原来的 `persona_template` 同时作为私聊和群聊的默认模板；
  - `enabled_conversations` 里的群放进群列表，私聊放进白名单。
- 全部做完后，在 `app_meta` 里写入 `config_bot_settings_migrated`。
- 迁移完成以后，配置里如果还写着这些挪走的键，启动时报错退出（退出码 78），提示到面板里改。规则和人设模板那次一样。
- 新加的配置 bot（数据库里还没有设置行）用默认值：
  - 显示名取 ID；
  - 没有管理员；
  - 私聊开放范围为 `admins`；
  - 没有启用的群；
  - 模板都用 `default`；
  - 不开技能。

**运行时**：

- bot 目录合并"配置里的身份信息 + 数据库里的设置"。
- 在面板里保存后，目录立即换成新快照。
- 适配器每 5 分钟从 core 拉一次 capabilities，所以群列表和私聊范围最多 5 分钟后在适配器那边生效。core 这边立即生效。（实施者决定：不额外实现推送）

**按会话类型选模板**：

- `BotConfig` 新增 `PrivateTemplate`、`GroupTemplate` 两个字段，以及方法 `TemplateFor(convType)`。
- 所有原来用 `bot.PersonaTemplate` 的地方，改为 `bot.TemplateFor(会话类型)`。
- 面板 bot 只有私聊，两个字段的值相同，沿用它现有的那个模板设置。

**面板**：

- 聊天页左栏里，配置 bot 也有"编辑"按钮。
- 编辑表单字段：
  - 显示名；
  - 管理员，每行一个平台用户 ID；
  - 私聊开放范围（下拉框）；
  - 私聊白名单，每行一个；
  - 启用的群，每行一个群 ID；
  - 私聊默认模板、群聊默认模板（下拉框）；
  - 技能（复选框）。
- ID、平台、平台自身 ID 只显示，不能改，并注明"在配置文件里修改"。
- 配置 bot 不能在面板里删除。

**接口**：

- `PUT /panel/api/bots/{id}` 对配置 bot 也开放，但只接受上面这些可改字段。
- 审计记为 `panel.bot.update`。
- 校验规则：
  - ID 列表里的每一项是非空字符串，不能有空白和冒号；
  - 模板必须存在于模板目录；
  - 技能必须是已加载的技能；群聊默认模板没有限制，但技能按会话类型过滤，沿用现有逻辑。

**文档**：更新 `docs/configuration.md`（`bots[]` 只剩身份字段，加升级说明）、`docs/panel.md` 和 `docs/deployment.md`。`conloom.example.yaml` 里删掉挪走的键。

## 4. 面板建议回复（类似 OpenWebUI）

- 只在面板聊天里有。
- 聊天窗口加一个"建议回复"开关，状态存在浏览器本地（localStorage），默认打开。
- 开关打开、bot 一轮回复全部发完（不再"正在输入"，最后一条消息是 bot 发的）后，前端请求生成建议：

  ```
  POST /panel/api/conversations/{key}/suggestions
  {after_seq: 最后一条消息的 seq}
  ```

- 服务端处理：
  - 只接受面板聊天。
  - 用回复模型（short_context）调用一次，并关闭思考（这次请求覆盖 `chat_template_kwargs.enable_thinking=false`，具体做法由实施者决定）。
  - 输入是这个聊天最近约 12 条消息，加上人设名。
  - 要求输出一个 JSON 数组，里面是 3 条以用户口吻写的下一句话，每条不超过 40 字，3 条之间要有差别（比如追问、推进剧情、换话题）。
  - 内容规则：
    - 保护模式下，在提示里加上和回复相同的保护底线，输出经过 `OutputProtected` 审查；
    - 开放模式下，输出经过 `Output` 审查。
    - 不合格的条目丢掉。
  - 结果按（会话，最后一条消息的 seq）缓存在内存里，最多保留 256 个会话（LRU）。同一条消息重复请求时直接返回缓存。
  - 超时 20 秒。失败时返回空列表，前端什么都不显示。
  - 用量按用途 `suggest` 记录。
  - 同一个会话同时只生成一次；已有请求在生成时，新请求等它完成后共用结果。
- 前端：
  - 建议显示成一排按钮，放在最后一条消息下面；点一下直接发送这句话。
  - 用户开始输入，或者发出新消息后，按钮消失。
  - 文字一律用 `textContent`，不用 `innerHTML`，不用内联样式。
- 文档：更新 `docs/panel.md` 和 `docs/api.md`。
