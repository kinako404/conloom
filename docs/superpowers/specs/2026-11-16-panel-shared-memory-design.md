# 面板聊天共用记忆，去掉"接管"

日期：2026-11-16
状态：已定稿，待实施。规则由部署者确认；标"实施者决定"的条目是我定的，部署者可以事后改。

## 1. 规则（部署者确认）

- **Telegram、QQ 的私聊**：一个对话一份独立记忆。一个人在一个平台上只有一个和 bot 的聊天窗口，所以对话和人是一一对应的。现状就是这样，不改。
- **Telegram、QQ 的群聊**：一个群一份记忆。现状就是这样，不改。
- **面板里新建的聊天**：同一个 bot 下的所有面板聊天共用一份记忆。每个聊天只是一段对话；bot 记得的事、对你的印象、好感度、状态和状态条，在这个 bot 的所有面板聊天之间通用。
  - 面板 bot 的所有聊天共用一份。
  - 配置 bot 在面板里新建的聊天之间也共用一份，但和它在平台上的记忆分开。
- **去掉"接管"**：不再能从面板以用户身份往 Telegram、QQ 的私聊里发消息。相关代码全部清理。

## 2. 目标与非目标

**目标**

1. 引入"记忆范围"。平台对话的记忆范围就是它自己的会话键；面板聊天的记忆范围是这个 bot 的面板共享范围。
2. 下面这些按记忆范围读写：
   - 摘要和整理游标；
   - 对人的备注和好感度，以及它们的修订记录；
   - "忘记"时间；
   - 语义检索的分块；
   - 状态、状态条和状态条事件。
3. 下面这些仍按单个聊天：
   - 聊天记录（"近期消息"只来自当前聊天）；
   - 人设版本、策略、任务、发件箱、定时（"回来说话"在设定状态的那个聊天里说）。
4. 删除和忘记：
   - 删掉一个面板聊天：删它的聊天记录，以及由这些记录生成的语义分块；共享的摘要、备注、好感度、状态保留。
   - 删掉面板 bot：连同它的共享记忆一起清空。
   - 在任意面板聊天里说"/忘记我"，或在面板、API 里点忘记：清掉共享记忆里关于这个人的部分。
5. 迁移：已有面板聊天的记忆并入共享范围，不丢。
6. 去掉"接管"：
   - 面板只能往面板新建的聊天里发消息；
   - 聊天页左栏只列面板聊天；
   - 会话页只对面板聊天显示"在聊天页打开"；
   - 删掉只为接管存在的代码路径、错误、判断和文档。

**非目标**

- 平台私聊和面板聊天之间共享记忆。
- 群聊和私聊之间共享记忆。
- 把记忆范围做成可配置项。

## 3. 做法

只有一种合理做法：给面板聊天一个共享的"记忆范围键"，所有记忆类数据都按这个键存取。现有表结构不变，列名仍叫 `conversation_key`，只是面板聊天的这一列存共享范围键。

考虑过、没采用的做法：

- **在多个聊天之间同步复制记忆**：写放大，容易不一致。
- **把一个 bot 的面板聊天合并成一个会话**：会破坏"对话就是对话"，聊天记录、人设、策略都混在一起。

### 3.1 记忆范围键

- 新增 `memory.ScopeKey(conv store.ConversationRecord) string`：
  - 平台对话返回自己的会话键；
  - `platform == panel` 的私聊返回 `<botID>:panel:private:~shared`。
- 共享范围键可以被现有的会话键解析函数正确解析，类型为私聊、平台为面板。`~shared` 不会和生成的面板聊天 ID（`panel_…`）冲突。
- 所有读写上面"目标 2"所列数据的地方，都先把会话换算成范围键。不能有漏掉的地方：实施时用 grep 列出所有用到这些表的读写点，并逐一说明。

### 3.2 整理（记忆整合）

- 调度按范围进行：同一范围内的多个面板聊天只整理一次。
- 素材是范围内所有聊天、`seq` 大于游标的消息。`messages.seq` 全局自增，可以直接当游标。
- 这些消息按 `seq` 排序；每条消息带上它所在的聊天标识，让整理模型知道它们来自不同的对话。（实施者决定）
- "忘记"之后的截断按范围内的 `forgotten_at` 计算。
- 共享记忆的设置（开关、字数上限、整理频率），取这个范围内最近有消息的那个面板聊天的策略。（实施者决定）
- 整理时的内容规则（保护模式第 6 条，或开放模式下人设的 `memory_rules`），取同一个聊天的人设。

### 3.3 回复时注入

- 记忆块、关系提示、状态块都按范围读取。
- "近期消息"仍然只来自当前聊天。

### 3.4 语义检索

- 每个聊天的分块仍按"一个聊天的一段连续消息"生成，便于删除聊天时一起删掉。
- 检索在整个范围内进行：
  - 平台对话只查自己；
  - 面板聊天查这个 bot 所有面板聊天的分块。
- 存储方式由实施者决定：分块表增加范围列，或者查询时按范围展开出所有会话键再查。要求检索结果和删除都正确。

### 3.5 状态和状态条

- 状态行和状态条数值按范围存：
  - 在面板聊天 A 里让她去洗澡，切到面板聊天 B，她也在洗澡。
  - "回来说话"的定时仍然挂在聊天 A 上，到点在 A 里说话；说完清除共享状态。
- 设定状态的那条记录里要能看出是在哪个聊天设的，用于决定回到哪里说话。
- 面板聊天不会主动找人（现有规则），不受影响。

### 3.6 删除与忘记

- 删除面板聊天（`DeletePanelChat`）：
  - 照常删这个会话键下的所有数据；
  - 另外删除这个聊天在共享范围里的语义分块；
  - 如果共享状态是在这个聊天里设的，同时清除状态和它的定时。
- 删除面板 bot：删完所有聊天后，再删共享范围下的全部记忆数据，包括摘要、备注、修订记录、分块、状态、状态条和事件。
- 忘记（`/忘记我`、面板、API）：作用于范围。

### 3.7 迁移

- 启动时执行一次，用 `app_meta` 键 `panel_memory_scoped` 标记是否已经做过。
- 每个 bot 的面板聊天按下面规则合并到共享范围：
  - 只有一个聊天有记忆：直接改键。
  - 多个聊天都有记忆：
    - 摘要取最近整理过的那个；
    - 每个人的备注和好感度取最近更新的那行；
    - 修订记录全部改键保留；
    - 分块全部改键或标上范围；
    - 状态取还没过期、到期最晚的那个；
    - 状态条每一条取最近更新的。
- 整个迁移在一个事务里完成，记一条审计 `memory.scope.migrate`，日志写明每个 bot 合并了几个聊天。

### 3.8 去掉"接管"

需要删掉或改掉的地方（实施时 grep 核对，不限于此）：

- core：
  - `SubmitPanel` 只接受面板聊天，平台对话返回 `ErrNotPanelChat`；
  - 删掉 `ErrNoUserYet`；
  - 删掉"以平台对话最近的用户身份发言"的逻辑；
  - 删掉"平台对话里的面板消息，回复只投递到面板"的分支（`replyChannel` 里平台对话用面板通道的情况）；
  - 删掉"平台对话的面板消息不提供 `set_status`"的判断。
- store：
  - 删掉 `UserMessageTimes` 里排除 `channel = 'panel'` 的条件，因为平台对话里不会再有新的面板消息；
  - `channel` 列和面板聊天自己的面板通道照常保留；
  - 发件箱按通道领取的逻辑保留，面板聊天还要用。
- panel：
  - `/chats` 只返回面板聊天，去掉 `takeover` 字段；
  - 往平台对话发消息返回 400；
  - 聊天页去掉"接管"标记和提示文字；
  - 会话页"在聊天页打开"只给面板聊天。
- 历史数据：以前接管时发的消息仍然留在平台对话的记录里。消息页可以继续显示"面板"标记，作为历史信息。
- 文档：
  - `docs/panel.md`、`docs/architecture.md`、`docs/usage.md` 里关于接管的说明全部删掉或改写；
  - `2026-11-14-panel-chat-design.md` 是历史设计稿，不改。

### 3.9 面板显示

- 面板聊天的"记忆"标签页和"自主"标签页上加一行说明："这个 bot 的所有面板聊天共用这份记忆"。
- 页面显示和修改的都是共享范围里的数据。
