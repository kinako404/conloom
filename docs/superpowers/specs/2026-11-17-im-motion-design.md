# TG 风格聊天界面的动画

日期：2026-11-17
状态：部署者确认"开工"。下面列出的动画都是我提出的方案，部署者照单认可。

## 为什么

TG 风格界面（`#/im`）目前没有任何动画。"正在输入…"是写死的文字，消息、菜单、建议回复都是直接出现、直接消失，显得生硬。部署者要求增加适当的动画，并点名了"正在输入…"。

## 范围

- 只改 TG 风格界面，也就是 `.chat-app` 下面的部分。
- 老聊天页（`.chat-classic`）和其他页面都不改。
- 只用 CSS 动画和过渡，不加依赖。JS 只负责切换类名，以及区分哪些是新到的消息。
- 时长控制在 150–250ms，缓动用 `ease-out` 或 `cubic-bezier(.2,.8,.2,1)`。"正在输入"的点是循环动画，一轮约 1.2s。
- 用户系统开启"减少动态效果"（`prefers-reduced-motion: reduce`）时：
  - 关闭以上所有动画和过渡；
  - "正在输入"的三个点保持静止显示。

## 具体动画

1. **正在输入**
   - 文字改成"正在输入"，后面跟三个小点，依次闪烁（透明度和位移循环变化，错开相位），颜色用强调色。
   - 出现、消失时淡入淡出约 150ms。
   - 不出现时，名字下面的那一行高度保持不变，避免顶栏跳动。
2. **新消息**
   - 轮询新拿到的消息、自己刚发出的消息：从下方 8px 处淡入，同时从 0.98 放大到 1。
   - 变换原点：自己的气泡在右下，角色的气泡在左下。
   - 打开聊天时首次加载的历史消息不加动画。
3. **建议回复**
   - 按钮依次淡入，每个错开约 40ms。
   - 悬停时背景平滑过渡；按下时缩小到 0.97。
4. **菜单**
   - ≡ 菜单从左上角展开，⋮ 菜单从右上角展开：透明度从 0 到 1，同时从 0.95 放大到 1，约 150ms。
   - 关闭直接消失即可（实施者决定）。
5. **聊天列表**
   - 行和文件夹的背景色在悬停、选中时过渡约 120ms。
   - 未读角标出现时，或数字变化时，从 0.6 放大回弹到 1，约 200ms。
   - 列表在内容没有变化时不重绘（现有逻辑），所以角标不会每 5 秒弹一次。
6. **切换聊天**
   - 电脑上对话区内容淡入约 150ms。
   - 手机（窄屏）上打开聊天时，对话页从右侧滑入；返回时列表从左侧滑入，各约 200ms。
7. **发送按钮**：按下时缩小到 0.92，禁用、启用状态有透明度过渡。

## 不做

- 不做发送失败时的抖动、消息删除动画、拖拽和手势。
- 不做骨架屏和加载占位动画。

## 方案

- **A（选定）**：CSS 关键帧和过渡，加少量类名切换。
- **B（没采用）**：Web Animations API 或引入动画库。没有必要，而且项目不加依赖。
