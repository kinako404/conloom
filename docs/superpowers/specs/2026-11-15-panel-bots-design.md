# 面板 Bot 设计：在面板里新建只在面板聊天的角色

日期：2026-11-15
状态：草稿，待部署者确认。标"实施者决定"的条目由我决定，部署者可以改。

## 1. 为什么做

部署者想在 Web 面板里长期养几个不同的角色。每个角色有自己的名字、默认人设、技能和记忆，不接 QQ 或 Telegram，只在面板里聊。

现在的 bot 只能写在配置文件里，加一个就要改配置、重启服务。而且配置校验明确不允许平台填 `panel`。

## 2. 目标、非目标、反目标

**目标**

1. 面板里有一个"Bot"页面，能看到所有 bot。配置文件里的 bot 只读；面板 bot 可以新建、编辑、删除。
2. 新建面板 bot 时填三样：
   - 名字：必填，1–32 字。
   - 默认人设模板：从配置里已有的人设模板中选，默认 `default`。
   - 技能：从已加载、支持私聊的技能里多选，默认全选。
3. 建好立即生效，不用重启。所有列出 bot 的地方都能看到它：新建聊天的下拉框、概览、会话筛选、任务筛选、用量等。
4. 编辑名字、默认人设模板、技能，下一次回复就生效。默认人设只影响之后新建的聊天，已有聊天各自的人设在会话的人设页里改。
5. 删除面板 bot 时，要先输入它的名字确认。删除会清掉它名下所有聊天和数据（消息、记忆、状态、状态条、定时等），然后删掉 bot 本身。模型用量统计和审计记录保留（见 4.8）。
6. 重启后面板 bot 都还在。
7. 新建、编辑、删除各记一条审计：`panel.bot.create`、`panel.bot.update`、`panel.bot.delete`。

**非目标**

- 面板 bot 接入 QQ、Telegram 或任何平台适配器。
- 在面板里修改配置文件里的 bot。
- 给面板 bot 单独配模型、默认策略或管理员。它们沿用 `default_private_policy`，会话级的策略照常可改。面板用户就是这些聊天的管理员，这一点和现在的面板聊天一样。
- 面板 bot 参与群聊。
- 给面板 bot 发网关令牌。网关令牌仍然只来自配置文件。

**反目标**（技术上能跑但算失败）

- 重启后面板 bot 或它的聊天不见了。
- 面板操作改到了配置文件里的 bot。
- 删一个 bot 时误删了别的 bot 的数据。
- bot ID 冲突，导致消息串到别的 bot。
- 面板 bot 绕过内容规则：人设模板里的 `minor`/`adult` 照常生效，保护模式不变。
- 新建、编辑、删除时，正在进行的回复报错或读到半新半旧的 bot。

## 3. 考虑过的做法

- **A. 存进数据库，面板里直接建、改、删（部署者选定）**：不用重启，加角色最方便。代价是代码里约 20 处直接从配置取 bot 的地方，要统一改成从"配置 bot + 面板 bot"的合并列表里取。
- **B. 面板改写配置文件后重启**：服务没有配置文件的写权限，文件里的中文注释会在回写时全部丢失，每次新建都要重启并打断进行中的对话。放弃。
- **C. 只放开配置里的平台限制**：改动最少，但界面上不能新建，不满足需求。放弃。

## 4. 设计

### 4.1 ID 和冲突

- 面板 bot 的 ID 由服务自动生成：`panel-` 加 8 位小写字母和数字，比如 `panel-k3x9q2ma`。界面上主要显示名字，ID 作为辅助信息。
- 配置文件里的 bot ID 不允许以 `panel-` 开头，配置校验时报错。这样两类 ID 永远不会冲突。现有的 `bot_main`、`bot_tg` 不受影响。
- 名字不要求唯一，但新建或改名时，如果和已有 bot（包括配置 bot）重名，界面提示一句，不阻止。（实施者决定）

### 4.2 存储

迁移 `0013_panel_bots.sql`：

```sql
CREATE TABLE panel_bots (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  persona_template TEXT NOT NULL,
  skills TEXT NOT NULL,          -- JSON 字符串数组
  created_by TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

- 新建时，在同一个事务里往 `bot_instances` 插入一行，平台为 `panel`；改名时同步更新它的名字。删除 bot 时这一行保留（见 4.8）。配置 bot 在启动时照常往 `bot_instances` 写入。
- 沿用现有约定：所有列 `NOT NULL`，时间用 `fmtTime` 格式。
- 备份用的是 `VACUUM INTO`，新表会自动包含在内。

### 4.3 统一的 bot 目录

- 配置里的 `Config.Bots` 仍然只表示"配置文件里写的 bot"。
- 新增一个 bot 目录，提供两个方法：
  - `Bot(id)` 按 ID 取一个 bot；
  - `All()` 列出全部 bot，先配置 bot，再按创建时间列面板 bot。
- 面板 bot 在目录里表现为一个 `BotConfig`：`Platform` 为 `panel`，`PrivateChat` 为 `admins`，没有 `PlatformSelfID`、`Admins` 和 `EnabledConversations`。
- 目录必须支持并发读：新建、编辑、删除时，正在跑的回复读到的是完整的旧值或完整的新值，不会读到一半。
- 现有所有 `cfg.Bot(id)` 和遍历 `cfg.Bots` 的地方（core、memory、search、panel、gateway、app）都改用目录。配置校验和启动时登记 `bot_instances` 这两处仍然只看配置 bot。
- 具体做法由实施者决定，比如给 `Config` 挂一个原子指针，或者新建一个独立类型再注入各组件。要求只有一个：所有组件看到的是同一份。

### 4.4 校验

- 名字：去掉首尾空白后 1–32 字，不能含控制字符和换行。
- 默认人设模板：必须是人设模板目录里存在的名字。目录包括配置文件里的模板和在面板里新建的模板，见《人设模板在线编辑与外观参考》设计（`2026-11-15-persona-templates-appearance-design.md`）。
- 技能：每一项都必须是已注册的技能，并且允许在私聊里用（用现有的技能注册表检查）。可以一项都不选。
- 面板 bot 最多 50 个。（实施者决定）
- 校验不通过返回 400，并给出能看懂的中文原因。

### 4.5 启动时引用失效

面板 bot 引用的人设模板或技能可能已经不存在了（模板从配置文件里删掉，或者在面板里被删除；技能从配置或技能目录里去掉）：

- 人设模板不存在：记一条警告，运行时改用 `default` 模板。面板上的这个 bot 标注"模板已不存在"。
- 某个技能不存在：记一条警告，运行时忽略这个技能，面板上同样标注。
- 两种情况都不阻止服务启动。（实施者决定）

### 4.6 聊天

- 面板 bot 只能有面板聊天，复用现有的 `CreatePanelChat`，会话键形如 `panel-k3x9q2ma:panel:private:<id>`。
- 平台适配器以配置 bot 的身份连接，不可能替面板 bot 上报事件。即便如此，core 收到非 `panel` 平台的事件、而 bot 是面板 bot 时，也要拒绝。
- 人设、记忆、状态、状态条、策略都按会话保存，和现有面板聊天一样。
- 主动找人：面板聊天本来就不会主动找人，状态结束后回来说话仍然可用，规则不变。
- 记忆整理、语义索引、自主唤醒这些后台任务，按会话的 bot ID 从目录取 bot。bot 已被删除时直接跳过，不报错。

### 4.7 编辑

- 改名：只影响之后显示的名字，以及系统提示里的 bot 名字。人设里写了角色名时，人设的角色名优先，这是现有规则。系统提示缓存的键里含 bot 名字，改名后会自然失效。
- 改默认人设模板：只影响之后新建的聊天，以及已经建好、但机器人还没回复过的聊天。聊天的人设在第一次回复时才定下来，这是现有行为，不改。（实施者决定）
- 改技能：下一次回复生效。

### 4.8 删除

1. 把 bot 标为"删除中"。之后新建聊天、发消息都会被拒绝，返回 409。
2. 用现有的 `DeletePanelChat` 逐个删掉它名下的聊天。它会取消任务、等任务停下、删数据、清缓存。
3. 如果某个聊天因为任务停不下来而删除失败，整个删除就停在这里，返回 409。已删的聊天不恢复，bot 也不删，"删除中"标记撤掉，可以重试。
4. 所有聊天都删掉后，在一个事务里完成三件事：
   - 删掉 `panel_bots` 里的行；
   - 删掉这个 bot ID 下还残留的聊天相关记录，例如没发过消息的聊天留下的 `users` 行、被忽略消息留下的 `events` 行；
   - 保留 `bot_instances` 里的行，因为它存着名字。

   然后从目录里移除这个 bot，并记审计。
5. 模型用量（`model_calls`）和审计记录保留：它们是统计和管理记录，不是聊天内容。用量页按 `bot_instances` 里存的名字显示已删除的 bot，标注"已删除"。（实施者决定）
6. 删除时请求体要带上 bot 名字作为确认，名字不一致返回 400。

### 4.9 面板：聊天页（部署者 2026-11-15 修订）

不单独做 Bot 页，Bot 管理并进新的"聊天"页。

- 顶部导航在"会话"前面加"聊天"，地址为 `#/chat` 和 `#/chat/<会话键>`。刷新或分享链接都能回到同一个聊天。
- 布局：
  - **左栏**：按 bot 分组列出可聊的私聊。每组的标题是 bot 名字，配置 bot 后面标"配置"。
    - 面板新建的聊天直接列出。
    - 平台私聊（Telegram、QQ）也列出，标"接管"。点进去就是现在的接管模式：以用户身份发消息，回复只显示在面板里。
    - 每组有"新建聊天"按钮。面板 bot 的组标题旁边有"编辑""删除"；配置 bot 的组注明"在配置文件里修改"。
    - 左栏最上面有"新建 Bot"按钮。
  - **右栏**：现在会话页"聊天"标签里的聊天窗口，原样搬过来。没选聊天时显示提示。
  - 切换聊天时不重新加载左栏，避免闪烁。
- 会话详情页去掉"聊天"标签，所有会话默认打开"消息"标签。私聊会话加一个"在聊天页打开"链接。
- 会话列表页的"新建聊天"按钮保留，建好以后跳到聊天页。
- "新建 Bot""编辑 Bot"表单：名字、人设模板下拉框（来自模板目录）、技能复选框（附技能说明）。删除对话框要输入 bot 名字确认。
- 新建聊天对话框的下拉框里，面板 bot 显示为"名字（面板）"。
- 现有的约束照旧：不用 `innerHTML`，不用内联 `style`，不引用外部链接，写操作带 CSRF，显示文字一律用 `textContent`。

### 4.10 接口

- `GET /panel/api/bots`：列出全部 bot，带来源、默认人设、技能、聊天数、最后一条消息、失效标注。
- `GET /panel/api/chats`：给聊天页左栏用。按 bot 分组，返回每个 bot 的私聊列表，每项包括会话键、显示名、平台、是否接管、最后一条消息的时间，按最后一条消息从新到旧排序。每个 bot 最多返回 200 个。
- `POST /panel/api/bots`：请求体 `{name, persona_template, skills}`，返回新建的 bot。
- `PUT /panel/api/bots/{id}`：请求体同上，各字段都必填。配置 bot 返回 403。
- `DELETE /panel/api/bots/{id}`：请求体 `{confirm_name}`。配置 bot 返回 403，聊天删不掉返回 409。
- 错误码：参数不合法 400，找不到 404，删除中或忙 409，core 服务不可用 503。和现有接口一样要求会话登录、同源和 CSRF。
- 现有接口里返回 bot 列表的地方（概览、配置视图、会话列表的筛选）一律带上面板 bot。
