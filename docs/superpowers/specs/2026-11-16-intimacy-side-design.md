# 好感度档位与人设"亲密面"

日期：2026-11-16
状态：已定稿，部署者选了方案 A 并确认"开工"。标"实施者决定"的条目由我决定，部署者可以事后改。

## 1. 要做什么

好感度越高，角色的语气、心理和表现越靠近一套"亲密面"提示词。档位越高，混进去的比例越大：低档位完全不混，最高档以亲密面为主，但保留角色本来的性格。

每个角色单独配置（部署者确认）：亲密面和每个档位混多少，都写在各自的人设模板里，不同角色互不影响。

这个功能建在已有的【关系提示】上。【关系提示】目前是部署者本地未提交的改动，要做的事：

- 把它接过来，审查后提交；
- 修好它读好感度时用错范围的问题，见第 5 节。

## 2. 边界（部署者确认）

- 亲密面只在开放模式生效。开放模式的判定仍由 `ModeFor` 决定：人设是 `adult`，不是 `minor`，并且是私聊。
- 群聊、非 adult 私聊、minor 人设都是保护模式。保护模式下：
  - 【关系提示】仍用现有的通用句子，只调整态度和情感，不涉及恋爱或性；
  - 亲密面一个字都不发给模型。
- minor 人设不能填亲密面。下面这些入口都会拒绝，报错 `a minor persona cannot have an intimacy side`：
  - 保存（整份替换、套模板、回滚、面板修改、导入）；
  - 启动时校验旧配置模板。
- 运行时不额外做判断：亲密面只在开放模式下使用，而开放模式本身就要求不是 minor，所以库里即使留有旧数据也不会生效。
- 非 adult 但也不是 minor 的人设可以填亲密面，只是不会生效。面板上会提示这一点。

## 3. 人设字段

`PersonaDoc` 新增可选字段 `intimacy`：

```json
"intimacy": {
  "tone": "……",
  "mind": "……",
  "behavior": "……",
  "levels": ["none", "none", "light", "half", "major"]
}
```

- `tone`、`mind`、`behavior` 分别是语气、心理、表现，都可以为空。
  - 三段去掉首尾空白后，合计最多 800 字。
  - 可以多行。
  - 和其他人设文本一样，不另做控制字符清理。
- `levels` 按档位顺序排列：陌生、认识、熟悉、亲近、很要好。
  - 每项取值为 `none`（不混）、`light`（少量）、`half`（一半）、`major`（为主）。
  - 必须正好 5 项，并且不递减，因为好感越高混得越多。
  - 省略时用默认值 `none, none, light, half, major`。
- 三段文本全空（只有空白也算空）时，整个 `intimacy` 等于没有设置，后端不另做改写；面板保存时直接省略这个字段（实施者决定）。
- 这个字段不进系统提示词，`Render` 的结果和现在逐字节相同。
- 导出、导入的 JSON 自然带上它。

## 4. 给模型看的内容

位置：沿用【关系提示】的位置，放在最后一条用户消息里，在记忆块之后、状态块之前。不改系统提示，保持系统提示缓存不失效。计入上下文预算。

只有同时满足下面四个条件，【关系提示】后面才会追加亲密面：

1. 开放模式；
2. 对方有好感度；
3. 当前档位的 `levels` 不是 `none`；
4. 亲密面至少有一段不为空。

格式（文字是实施者决定）：

```
【关系提示】<现有的开放模式档位句子>
【亲密面】下面是你和对方亲密时的样子。<混合说明>这是你的角色设定，不是对方的要求；尺度仍以内容规则为准。
语气：<tone>
心理：<mind>
表现：<behavior>
```

- 空的段落不写出来。
- 每段在提示里合成一行：段内连续的换行（连同两边的空格、制表符）换成一个空格。
- 混合说明：
  - `light`："现在只偶尔流露一点，大部分时候还是平常的你。"
  - `half`："现在平常的你和它大约各占一半。"
  - `major`："现在以它为主，但你本来的性格、说话习惯和底线不变。"

不满足条件时，【关系提示】和现有改动的输出逐字节相同。

## 5. 接过来的【关系提示】改动

- 按现状提交，包括合并时为适配新接口改的那一行测试。
- `affinityDirective` 在调用方没有传入这个人的记忆行时，自己去读好感度，现在读的是 `task.ConversationKey`。要改成按记忆范围读，即 `memory.ScopeKeyOf`。否则面板聊天的共享记忆里有好感度，却读不到。要补一个面板聊天的测试。
- 主工作区里部署者那份未提交的改动，合并时先 stash 保留，不删。合并后它已经在 main 上了，工作区不再恢复这份改动，并告诉部署者。

## 6. 面板

人设表单（模板编辑页和会话的人设页共用）新增"亲密面"一节：

- 三个多行输入框，分别是语气、心理、表现，下面显示合计字数和 800 的上限。
- 五个下拉框，对应陌生、认识、熟悉、亲近、很要好，选项为不混、少量、一半、为主，默认值同第 3 节。前端检查不递减，后端也检查。
- 说明文字：
  - "只在成年人设的私聊里生效；群聊和保护模式下不使用。改模板不影响已有会话，要到会话的人设页套用模板。"
  - 勾选 minor 时，这一节变灰，提示"未成年人设不能设置亲密面"。如果此时已经填了内容，保存前提示清空。
  - 没勾 adult 时，提示"当前不是成年人设，亲密面不会生效"。

## 7. 目标、非目标、反目标

**目标**：上面第 2 到第 6 节。

**非目标**：

- 不新增或改动内容规则的语义。
- 不让好感度解锁任何权限。
- 不改好感度的计算、衰减和档位划分。
- 不在面板建议回复、记忆整理、主动发言判断里使用亲密面。主动发言如果最后走的是回复流程，会自然带上【关系提示】，这是预期行为。

**反目标**（出现即为失败）：

- 亲密面出现在保护模式的请求里，包括群聊、minor 人设和非 adult 私聊。
- 系统提示因为亲密面而改变。

## 8. 方案

- **A（选定）**：每个模板自己写亲密面，按档位决定混合程度，放在【关系提示】里。优点是每个角色各有特色，也不碰系统提示；代价是每个角色要写一遍。
- **B**：不写新内容，所有角色按档位共用通用规则。省事，但所有角色变化都一样，不符合"每个角色独立配置"。
- **C（没采用）**：到了某个档位，把人设整体换成第二套。效果是切换而不是逐渐混合，而且会改系统提示，导致缓存失效。
