# 面板聊天设计：接管私聊用户一方、在面板新建聊天

日期：2026-11-14
状态：已定稿，待实施（部署者已确认：接管时，回复只显示在面板里，不发到原平台）

## 1. 为什么做

部署者想在 Web 面板里直接和机器人聊天，不必每次切换到 Telegram：

- **调人设、调节奏**：改完人设或分条策略后，在面板里就能马上试。
- **接着私聊往下说**：在一个已有的私聊里扮演用户一方，用同一套人设、记忆和上下文继续对话。
- **在面板里新开测试会话**：从零开始聊，不影响任何真实会话。

## 2. 目标、非目标、反目标

**目标**

1. **接管私聊的用户一方**（Telegram、QQ 等平台的私聊会话）：
   - 在会话页里打字，消息以该会话的用户身份进入这个会话，走正常流程：输入审查、等停顿、合并、打断重来、限流、人设、记忆、分条。
   - 对**面板发出的消息**，机器人的回复只投递到面板，原平台的适配器永远拿不到。
   - 这些对话照常进入聊天记录和记忆。之后在原平台继续聊时，机器人都记得。
   - 原平台照常工作：用户在 Telegram 里发的消息，回复仍然发到 Telegram。
2. **在面板里新建聊天**：
   - 选择一个机器人实例，填写自己的称呼（默认是面板用户名），新建一个平台为 `panel` 的私聊会话。
   - 面板用户就是这个会话的用户，并视为该机器人的管理员，可以用管理员命令。
   - 不受该机器人 `private_chat` 白名单的限制。
   - 人设取机器人配置的默认模板，之后可以在人设页切换。策略取私聊默认策略。
   - 可以删除，删除时清掉该会话的全部数据。
3. **聊天窗口**：
   - 在私聊会话页新增"聊天"标签；对 `panel` 平台的会话，打开时默认就是这个标签。
   - 按时间顺序显示，最新的在底部，约每 1.5 秒增量拉取一次。
   - 回车发送，Shift+回车换行。
   - 机器人正在生成，或还有分条没到时间时，显示"对方正在输入…"。
   - 在原平台的会话里，面板发出的消息带"面板"标记，方便区分。
4. **分条节奏**：面板也遵守分条的间隔，每条到时间才显示。
5. **审计**：
   - 每条从面板发出的消息记一条审计，种类 `panel.message`，只记会话和消息 ID，不记正文；
   - 新建和删除聊天也各记一条。

**非目标**

- 群聊：不支持接管，也不能在面板里新建群聊。
- 把面板发出的消息同步到原平台。Telegram 机器人不能以用户身份发言，这本来就做不到。
- 多个面板用户同时聊同一个会话时的冲突处理。按到达顺序处理即可。
- 附件、图片。只支持纯文本。

**反目标**

- 面板消息的回复被发到 Telegram 或 QQ。
- 原平台消息的回复被投递到面板，用户在原平台收不到。
- 面板的一个会话阻塞同一会话里原平台回复的投递，或者反过来。
- 面板消息绕过输入审查、限流或内容模式（保护/开放）。
- 删除聊天误删其他会话的数据，或者删掉非 `panel` 平台的会话。
- 公开仓库出现真实 ID 或昵称。

## 3. 方案取舍

| 方案 | 结论 |
|---|---|
| **面板通过进程内调用提交事件，按消息记录来源通道，回复按通道投递（选用）** | 复用整条处理流程；用通道字段分流，适配器侧只需在拉取时过滤 |
| 面板伪装成一个外部适配器，通过 HTTP 提交 | 要给面板单独发令牌，还要处理"同一个会话、两个适配器"的投递问题，绕远了 |
| 接管期间暂停原平台的适配器 | 会影响原平台上的真实用户，部署者也没有这个需求 |

## 4. 设计

### 4.1 通道

- 新增迁移（编号接在最新迁移之后）：
  - `messages` 表加 `channel TEXT NOT NULL DEFAULT ''`；
  - `outbox_actions` 表加同样的列。
- 取值：`''` 表示原平台，`panel` 表示面板。旧数据都是 `''`。
- 面板提交的消息，`channel = panel`。
- **任务的通道**取它最后一条触发消息的通道。合并、打断重来之后同样按这个规则取。任务生成的所有动作都带这个通道。
- 主动发言、记忆整理这类不是由消息触发的输出，走原平台。`panel` 平台的会话没有原平台，主动发言的投递也走面板。
- **拉取规则**：
  - 适配器的 `LeaseOutbox` 只看 `channel = ''` 的动作，按会话排队的"队首"判断也只在这个通道内进行；
  - 面板投递器只看 `channel = panel` 的动作。
  - 两个通道互不阻塞，各自保持顺序。

### 4.2 面板投递器

- core 里新增一个后台循环，周期性拉取 `channel = panel` 的到期动作（分条的最早发送时间同样生效），然后直接确认投递。
- 确认时：
  - 机器人消息的平台消息 ID 用合成值，例如 `panel:<action_id>`；
  - 机器人消息本身也记 `channel = panel`。
- 分条到期时，现有的唤醒机制要同时唤醒这个循环，不能只靠轮询，否则节奏会变差。
- 关闭顺序：投递器在发件箱和数据库之前停止。

### 4.3 提交

- 面板通过一个接口调用 core 提交事件（与 gateway 同一个提交入口），事件里带上通道。
- **接管已有私聊**：
  - 发言人用这个会话已知的用户（会话的平台用户 ID）；
  - 显示名取该用户最近一次的显示名；
  - 平台消息 ID 用 `panel:<随机 ID>`，幂等键随之生成。
- **`panel` 平台的会话**：
  - 发言人 ID 为 `panel:<面板用户名>`，显示名为新建时填的称呼；
  - 这个发言人视为该会话所属机器人的管理员；
  - 白名单检查对 `panel` 平台不生效。

### 4.4 新建与删除

- 新建：会话 ID 为 `panel_<随机>`，会话键 `<bot>:panel:private:<id>`，并把显示名写入用户表。
- 删除：只允许 `panel` 平台的会话。在一个事务里删除这个会话键下所有表的数据，表的清单由实施者对照 schema 列全，然后删除会话本身。

### 4.5 面板接口

所有写接口都需要 CSRF 头，并写审计。

| 接口 | 用途 |
|---|---|
| `POST conversations/{key}/messages` | 请求 `{text}`，返回 202 `{message_id}`。只限私聊，非私聊返回 400。文本为空或超过 2000 字返回 400 |
| `GET conversations/{key}/chat?after=<seq>` | 返回 `{messages:[Msg…], typing:bool, next_after:seq}`。Msg 在现有字段之外加 `channel`。`typing` 表示这个会话有排队中或运行中的任务，或者面板通道还有没到时间的分条 |
| `POST chats` | 请求 `{bot_instance_id, display_name}`，返回 201 `{key}` |
| `DELETE conversations/{key}` | 只限 `panel` 平台，返回 204 |

### 4.6 前端

- 会话列表加"新建聊天"按钮，弹出表单：选择机器人、填写称呼，提交后跳到新会话的"聊天"标签。
- 新增"聊天"标签：
  - 消息气泡分左右，自己在右，机器人在左；
  - 带"面板"标记，滚动保持在底部；
  - 显示"对方正在输入…"；
  - 发送失败时显示服务端返回的错误文字，并保留输入框里的内容。
- `panel` 会话的详情页有"删除这个聊天"按钮，点击后需要确认。
- 所有内容都用文本节点渲染。

## 5. 测试与验收

**通道与投递**：

- 面板消息的回复 `channel = panel`，适配器拉不到，面板投递器能拉到；原平台消息正好相反。
- 同一个会话两个通道互不阻塞。
- 合并后的任务按最后一条触发消息定通道。
- 分条节奏：面板投递器按到期时间逐条确认，到期时会被唤醒。

**提交**：

- 接管时，消息的发言人是该会话的用户，带 `channel = panel`，并经过输入审查和限流；
- 群聊会话返回 400；
- `panel` 会话的用户是管理员，能执行管理员命令；
- 不受白名单限制。

**新建与删除**：

- 新建后能聊；
- 删除后该会话键下的所有表都没有残留；
- 删除非 `panel` 平台的会话返回 400；
- 删除不影响其他会话。

**`chat` 接口**：

- 用 `after` 增量拉取；
- `typing` 在任务运行时为 true，所有分条都送达后为 false。

**端到端**：

- 面板新建聊天，发一句，收到回复；
- 接管 Telegram 私聊，发一句，回复只出现在面板，适配器拉不到；
- 随后从原平台发一句，机器人的回复走原平台，并且能引用面板里聊过的内容（检查上下文）。

**上线验收**：

- 在线上用面板接管 Telegram 私聊发一句，确认 Telegram 没有收到回复，面板里能看到；
- 新建一个面板聊天，聊两句，然后删除。

## 7. 实施前补充的决定

- 面板用户的发言人 ID 用 `panel_<面板用户名>`，不带冒号，因为会话键和多处代码按 `:` 切分。新建的会话 ID 用 `panel_<随机>`，同样不带冒号。
- 接管已有私聊时，发言人取这个会话最近一条用户消息的平台用户 ID 和显示名。会话里还没有用户消息时不能接管，返回 400。
- 删除面板聊天时，`model_calls`（用量统计）和 `audit_events`（审计）保留，其余按会话键清空。同时清掉内存里的状态：调度会话、人设和策略的缓存。
- 管理员判断统一到一个函数，`panel` 平台的发言人视为管理员。私聊白名单在三处放行 `panel` 平台：回复判定、记忆整理、语义索引。
- 面板投递器在发件箱的唤醒之外还有自己的唤醒入口。core 的通知同时发给发件箱和面板投递器。
