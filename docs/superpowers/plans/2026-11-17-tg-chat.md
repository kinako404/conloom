# 面板聊天页 Telegram 化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把面板聊天页改成 Telegram 桌面版的三栏布局（文件夹栏、聊天列表、对话区），全窗口，窄屏单栏切换。

**Architecture:** 接口 `GET /panel/api/chats` 只加字段（bot 头像、每个聊天的最后一条消息和消息数），存储层加一个批量取最后一条消息的查询。前端在现有原生 JS 视图上重写：`views/chats.js` 负责外壳、文件夹栏、列表、未读；`views/chat.js` 负责对话区（顶栏、气泡、日期分隔、建议按钮、输入栏）。

**Tech Stack:** Go（见 go.mod），SQLite，原生 JS + CSS（`internal/panel/web`，无构建、无依赖）。

**Spec:** `docs/superpowers/specs/2026-11-17-tg-chat-design.md`

## Global Constraints

- 公开仓库：代码、测试、文档、提交说明里不出现真实 ID、令牌、主机名、昵称、角色名；测试只用假数据（`qq-main`、用户 20001/29999、小明/小红、`example.invalid`）。
- 不加新依赖（Go 和前端都不加）；不引入前端构建步骤。
- 提交前 `gofmt -l .` 为空、`go vet ./...` 通过、相关包 `CGO_ENABLED=1 go test -race -count=1` 通过；改了 JS 的任务对改动的每个 JS 文件跑 `/usr/local/node/bin/node --check`。
- 提交说明英文 conventional 风格；界面文案中文，逐字使用设计和本计划给出的文案。
- 只改聊天页：其他页面的外观和行为不变；离开聊天页后顶部导航恢复。
- 浅色、深色两套主题都要能用（沿用 `style.css` 里现有的 CSS 变量和 `prefers-color-scheme`）。
- 现有能力不能丢：新建 Bot、编辑/删除 Bot（含配置 bot 的编辑对话框）、新建聊天、删除聊天、建议回复（含开关）、向上翻页加载历史、发送失败和被拦截的提示、面板只读用户（如有）的限制。

## Review Focus

1. 窄屏（手机）打开 `#/chat/<key>` 直链——期望直接显示对话区和"←"，点"←"回到列表；T2 静态检查 + 控制者部署后无头浏览器验收。
2. 从聊天页点 ≡ 菜单里的"会话"等链接离开——期望顶部导航恢复、其他页面布局正常；T2 测试（app.js 的切换逻辑静态检查）+ 验收。
3. 列表轮询期间对话区正在打字/输入——期望列表刷新不打断输入框内容和对话区滚动位置；T2 实现约束 + 验收。
4. 最后一条消息很长、含换行或 Markdown 符号——期望预览单行截断、不撑破布局；T1 测试（60 字 + "…"、换行合并）。
5. 没有参考图的 bot、名字是英文或表情开头——期望彩色圆底 + 第一个字符（按 Unicode 字符取，不切坏代理对）；T2 实现约束。

### Task 1: 接口——列表带最后一条消息、消息数和头像

**Files:**
- Modify: `internal/store/store.go`（或声明 `MessagesAfter` 的接口文件）加方法声明
- Modify: `internal/store/sqlite/memory.go`（`LastMessages` 实现，放在 `MessagesAfterIn` 附近）
- Modify: `internal/panel/bots.go`（`chatGroup`、`chatEntry`、`listChats`）
- Test: `internal/store/sqlite/` 对应测试文件、`internal/panel/` 里 `listChats` 的现有测试
- Docs: `docs/panel.md`（或列面板接口的文档）里 `GET /panel/api/chats` 的说明

**Interfaces:**
- Produces:
  - `LastMessages(ctx context.Context, convKeys []string) (map[string]store.MessageRecord, error)`：每个会话 `seq` 最大的一条；没有消息的会话不在结果里；`convKeys` 为空返回空 map、不查库。一条 SQL（如按 `conversation_key` 分组取 `MAX(seq)` 再连接）。
  - `chatGroup.Avatar string` json `avatar`：bot 私聊默认模板（`TemplateFor(ConvPrivate)` 或面板 bot 的模板）在模板目录里的 `appearance_image`；取不到为 `""`，读模板出错只记日志、不让整个接口失败。
  - `chatEntry.MessageCount int` json `message_count`（来自 `ConversationStats.MessageCount`）
  - `chatEntry.Last *chatLast` json `last`，`chatLast{Seq int64 "seq"; FromBot bool "from_bot"; At time.Time "at"; Text string "text"}`；无消息时 `null`
  - `Text`：消息文本里所有空白（含换行）连续段合成一个空格、去首尾空白；超过 60 个字符（rune）时取前 60 个再加 `…`。`FromBot` 与现有 `messageView` 判断 bot 消息的方式一致。

### Task 2: 外壳、文件夹栏、聊天列表、未读、窄屏

**Files:**
- Modify: `internal/panel/web/app.js`（聊天页时隐藏顶部导航、给 `<body>` 加类 `chat-app`，离开时还原）
- Modify: `internal/panel/web/views/chats.js`（`chatPage` 布局重写；对话框函数 `newChatDialog`、`botDialog`、`configBotDialog`、`deleteBotDialog` 复用不改语义）
- Modify: `internal/panel/web/style.css`（聊天页样式，全部挂在 `.chat-app` 下，避免影响其他页面）
- Test: `internal/panel/web/web_test.go`
- Docs: `docs/panel.md`（聊天页一节）

**Interfaces:**
- Consumes (Task 1): `GET chats` → `{bots:[{id,name,source,avatar,chats:[{key,title,platform,last_message_at,message_count,last}]}]}`
- Produces（给 Task 3）：`chatPane({ key, signal, hint, bot, onBack, onDelete })`：
  - `bot = { id, name, avatar }`：对话区顶栏用的角色名和头像（名字用 bot 名）
  - `onBack()`：窄屏"←"调用，回到列表（`go` 到 `#/chat` 并保留 `?bot=`）
  - `onDelete()`：⋮ 菜单"删除这个聊天"调用，走现有删除确认和接口，成功后刷新列表并回到列表
  - 本任务里 `chat.js` 只需接受这些参数而不报错；顶栏和菜单由 Task 3 实现
- 导出给 Task 3 复用：`avatarEl(bot, size)`（放在新文件 `views/avatar.js`）——有 `bot.avatar` 时 `<img class="avatar" src="api/persona-images/<id>?size=reply&v=<id>">`（`object-fit: cover`、圆形），否则彩色圆底 + 名字第一个 Unicode 字符（`[...name][0]`），颜色按 `bot.id` 的简单字符串哈希取 8 色之一；`size` 为像素直径。

布局与行为（设计第 2、4、5 节，文案逐字）：
- 三栏：文件夹栏（≡、"全部"、每个 bot 的头像 + 名字）、列表（搜索框占位 `搜索`；选中 bot 时一行"<bot 名> 编辑 删除"，删除只对面板 bot；行：头像、角色名、时间、预览——自己发的加 `你：`、未读徽章；浮动按钮 `✎`，`title` 为 `新建聊天`；空列表 `还没有聊天，点右下角的 ✎ 开始`）、对话区（未选中时居中标签 `选择一个对话开始聊天`）。
- ≡ 菜单项：`概览`、`用量`、`会话`、`人设模板`、`任务`、`审计`、`配置`（链接，与 `app.js` 的 `SECTIONS` 同源，不要另抄一份）、`新建 Bot`、当前用户名、`退出`。点菜单外关闭。
- 选中的文件夹存在网址 `?bot=<id>`；"全部"不带参数。
- 时间格式：当天 `HH:MM`，今年 `MM-DD`，更早 `YYYY-MM-DD`（用浏览器本地时区，与现有 `lib/format.js` 风格一致）。
- 列表行标题用 bot 名（不是 `title`）；同一个 bot 有多个聊天时，`title` 以小字显示在角色名后面（实施者决定，帮助区分）。
- 未读：`localStorage` 键 `conloom.chat.seen`，值为 `{ [key]: count }` 的 JSON。第一次见到的聊天记为当前 `message_count`；当前打开的聊天每次列表刷新时更新为最新 `message_count`；未读 = `message_count - seen`，≤0 不显示，>99 显示 `99+`。
- 列表每 5 秒刷新一次（`signal` 取消时停止）；刷新只替换列表区和文件夹栏的内容，不重建对话区，不打断输入。
- 窄屏（`(max-width: 699px)`，沿用 `NARROW`）：无聊天时显示文件夹（横排标签）+ 列表；有聊天时只显示对话区。

### Task 3: 对话区——顶栏、气泡、日期分隔、建议按钮、输入栏

**Files:**
- Modify: `internal/panel/web/views/chat.js`（`chatPane`）

- Test: `internal/panel/web/web_test.go`
- Docs: `docs/panel.md`（聊天页一节的对话区部分）

**Interfaces:**
- Consumes (Task 2): `chatPane({ key, signal, hint, bot, onBack, onDelete })`、`avatarEl(bot, size)`；`GET …/chat` 的 `typing`（已有）

行为（设计第 2、3 节，文案逐字）：
- 顶栏：窄屏时左侧 `←`（调用 `onBack`）；头像（`avatarEl(bot, 40)`）、bot 名、其下一行 `typing` 为真时显示 `正在输入…`；右侧 `⋮` 菜单：`会话详情`（链接到现有会话页）、`建议回复：开`/`建议回复：关`（切换，沿用现有 `localStorage` 键 `conloom.chat.suggestions` 和 `suggestionsOn`/`saveSuggestionsOn`）、`删除这个聊天`（调用 `onDelete`）。去掉输入框下面的复选框。
- 气泡：自己的消息右侧、强调色底白字；bot 的消息左侧、深色底；时间 `HH:MM` 在气泡右下角小字；不显示 `面板` 标签，只有 `channel` 存在且不是 `panel` 的消息才显示渠道标签；被拦截提示（`suppressedNote`）不变。
- 同一方连续消息为一组：组内间距小，只有组内最后一条有尾巴（CSS 伪元素）。
- 日期分隔：相邻两条消息本地日期不同时（以及第一条之前）插入居中标签：今年 `M月D日`，否则 `YYYY年M月D日`。翻页加载更早的历史时分隔线也要正确（插在新加载的段内和段与原第一条之间）。
- 建议回复：在最后一条 bot 消息下方，每条一个占满一行宽的圆角半透明按钮；点按即发送（沿用现有逻辑和防重复发送）。
- 输入栏：圆角 `textarea`，随内容自动增高，最多 6 行；右侧圆形按钮 `➤`（`title` 为 `发送`）；回车发送、Shift+回车换行、触屏设备保持现有行为（`TOUCH`）；发送中禁用按钮。
- 滚动、轮询（`POLL_MS`）、翻页（`HISTORY`、`PAGE`）逻辑不变。
