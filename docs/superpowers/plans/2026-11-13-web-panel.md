# Web 管理面板 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 ConLoom 加一个打包进二进制的 Web 管理面板：持久化每次模型调用的用量，登录后能看用量与性能、管理会话的策略/人设/记忆、浏览消息/任务/审计、查看打码配置。

**Architecture:**
- 用量：新建 `internal/usage` 包，异步批量写 SQLite `model_calls` 表；归属（bot、会话、任务）通过 ctx 传递。
- 面板：新建 `internal/panel` 包，在 core 现有 HTTP 服务的 `/panel/` 下提供静态页面和 `/panel/api/` JSON 接口，用 cookie 会话鉴权，会话存 SQLite。
- 前端：`internal/panel/web` 下的原生 ES 模块，通过 `go:embed` 打包。

**Tech Stack:** Go 1.26、modernc SQLite、标准库 `net/http`、`crypto/pbkdf2`、`embed`；prometheus client_golang（已有）；前端原生 JS 和 SVG。

**Spec:** `docs/superpowers/specs/2026-11-13-web-panel-design.md`

## Global Constraints

- 不新增 Go 依赖；不引入 npm 构建、CDN 或任何外部前端资源。
- `CGO_ENABLED=0` 必须能编译；`go test -race ./...`、`go vet ./...`、`gofmt -l .` 都要干净。
- 时间列沿用 `internal/store/sqlite/db.go` 的 `timeLayout`（定宽 RFC3339Nano，UTC）。
- 迁移编号：`0008_model_calls.sql`、`0009_panel_sessions.sql`。
- 密码哈希格式 `pbkdf2-sha256:<迭代次数>:<盐>:<哈希>`：盐 16 字节，盐和哈希用不带填充的 base64url，默认 600000 次迭代，最少 100000 次。
- cookie：名 `conloom_panel`，`HttpOnly`，`SameSite=Strict`，`Path=/panel/`，`Secure` 取 `panel.cookie_secure`。
- 登录限流：同一 IP 15 分钟内失败 5 次，或全局 15 分钟内失败 30 次，返回 429 并带 `Retry-After`。IP 只取 `RemoteAddr`。
- 列表接口 `limit` 默认 50、最大 200；用量统计范围最多 400 天，p50/p95 只在 ≤90 天时计算。
- `runtime.usage_retention` 默认 400 天（`9600h`）。
- 审计的 actor 为 `panel:<用户名>`；成员修订记录的来源为 `panel`。
- 公开仓库：测试只用假数据，比如 bot `qq-main`、群 `10001`、用户 `20001`、`小明`，主机 `example.invalid`。不得出现真实 ID、令牌、主机名、昵称。
- 界面文字用中文；所有用户数据用 `textContent` 或 DOM API 渲染，前端代码里不出现 `innerHTML`、`outerHTML`、`insertAdjacentHTML`、`document.write`、`eval`、`new Function`。

## Review Focus

1. **数据里带 HTML**：消息、昵称、人设、审计 detail 里含 `<script>`、`<img onerror>`，应当原样显示成文本。由 Task 7 的静态检查和 Task 8 的 e2e 覆盖。
2. **会话键里的特殊字符**：Telegram 群的 ID 是负数（`-1001234`），会话键里有冒号，键里还可能出现 `%`。经 `encodeURIComponent` 和 `PathValue` 必须能原样往返。由 Task 6b 测试覆盖。
3. **全新安装或空库**：没有会话、没有用量、没配 embedding 时，概览和各列表返回空数组或 `null`，不报错。由 Task 6a 和 6b 测试覆盖。
4. **用量参数不合法**：`from` 晚于 `to`、格式错误、超过 400 天，都返回 400；`to` 是当天时包含今天已有的数据。由 Task 6a 测试覆盖。
5. **使用中途会话过期**：接口返回 401 后，前端跳到 `#/login?next=<原路由>`，登录后回到原页面。由 Task 5 测试服务端的 401，Task 7 的 `api.js` 实现跳转。

## 接口约定（Task 6a/6b/6c 与 Task 7 共用）

所有路径的前缀都是 `/panel/api/`。时间为 RFC3339 UTC 字符串，可以为空的时间用 `null`。错误体为 `{"error":{"code","message","retryable","trace_id"}}`。

**鉴权**
- `POST login`：请求 `{"name","password"}`。成功返回 200 `{"user","csrf_token","expires_at"}`；失败返回 401 `UNAUTHORIZED`；被限流返回 429 `RATE_LIMITED`。
- `GET session`：返回同样的形状。
- `POST logout`：返回 204。

**概览**
- `GET overview` 返回：
  ```
  {"version","commit","started_at","timezone",
   "bots":[{"id","platform","name","last_seen_at"}],
   "live":{"queue_depth","outbox_pending","embedding_backlog","fts_backfill_remaining","breakers_open":["role"]},
   "today":{"calls","errors","prompt_tokens","completion_tokens","reasoning_tokens"}}
  ```

**用量**
- `GET usage?from=YYYY-MM-DD&to=YYYY-MM-DD&group=model|role|purpose|bot`：返回 `usage.Report`（见 Task 4）。
- `GET usage/calls?from&to&model&purpose&conversation&before&limit`：返回 `{"calls":[Call],"next_before":id|null}`。
  - Call 的字段：`id, at, bot_instance_id, conversation_key, task_id, purpose, role, model, prompt_tokens, completion_tokens, reasoning_tokens, estimated_tokens, latency_ms, outcome, finish_reason`。

**实时指标**
- `GET metrics/live` 返回：
  ```
  {"metrics":[{"name","help","type":"counter|gauge|histogram",
     "series":[{"labels":{…},"value"} | {"labels":{…},"count","sum","p50","p95"}]}]}
  ```

**会话**
- `GET conversations`：返回 `{"conversations":[Conv]}`。
  - Conv 的字段：`key, bot_instance_id, bot_name, platform, type, platform_conversation_id, message_count, last_message_at, paused, proactive_enabled, memory_enabled, persona_template, persona_version`。
- `GET conversations/{key}`：返回 Conv。
- 消息：Msg 的字段为 `seq, id, at, sender_id, sender_name, from_bot, text, reply_to`。
  - 浏览 `GET conversations/{key}/messages?before&limit`：返回 `{"messages":[Msg],"next_before":seq|null}`。
  - 检索 `GET …/messages?q&from&to&offset&limit`：返回 `{"messages":[Msg],"next_offset":n|null}`。
- 策略 `GET …/policy`：返回 `{"current":PV,"versions":[PV]}`。
  - PV 的字段：`version, policy`（GroupPolicy 的 JSON）`, reason, updated_by, created_at`。
- 人设 `GET …/persona`：返回 `{"current":PeV|null,"pending_template":string|null,"template_doc":PersonaDoc|null,"versions":[PeV],"templates":[string]}`。
  - PeV 的字段：`version, template, persona, reason, updated_by, created_at`。
- 记忆 `GET …/memory`：与 Bearer API 的 `GET /api/v1/conversations/{id}/memory` 完全相同。
- 修订记录 `GET …/memory/revisions?user_id=`：返回 `{"revisions":[{"id","user_id","field","old","new","source","reason","created_at"}]}`。

**任务与审计**
- `GET tasks?status&bot&conversation&before&limit`：返回 `{"tasks":[Task],"next_before":id|null}`。
  - Task 的字段：`id, bot_instance_id, conversation_key, status, command, priority, trigger, model_role, model, error_code, created_at, updated_at`。
- `GET tasks/{id}`：返回 `{"task":Task,"meta":TaskMeta,"actions":[Action],"model_calls":[Call]}`。
- `GET audit?kind&bot&before&limit`：返回 `{"events":[{"id","bot_instance_id","kind","actor","target","detail","created_at"}],"next_before":id|null}`。

**配置**
- `GET config`：返回 `{"config":{…}}`，是嵌套对象，秘密字段的值为 `"(已设置)"` 或 `"(未设置)"`。

**写接口**（都需要 `X-CSRF-Token` 头）
- `PUT conversations/{key}/policy`：请求体为 `PolicyPut`，返回 `{"current":PV}`。
- `POST …/policy/restore`：请求 `{"version","reason"}`，返回 `{"current":PV}`。
- `POST …/pause`、`POST …/resume`：返回 `{"current":PV}`。
- `PUT …/persona`：请求体为 `PersonaPut`，返回 `{"current":PeV}`。
- `PUT …/memory/members/{user_id}`：请求体为 `MemberMemoryPut`，返回与 API 相同的成员 JSON。
- `DELETE …/memory/members/{user_id}`：返回 204。
- `POST …/memory/consolidate`：返回 202 `{"accepted":true}`。
