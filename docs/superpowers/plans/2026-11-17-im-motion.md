# TG 风格聊天界面动画 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 `#/im` 的 TG 风格聊天界面加上设计里列出的 7 类动画，并尊重"减少动态效果"。

**Architecture:** 全部用 CSS 关键帧/过渡实现，规则都挂在 `.chat-app` 下；JS 只加少量类名（新到消息的 `is-new`、"正在输入"的点、角标变化的 `bump`、窄屏进出方向）。

**Tech Stack:** 原生 JS + CSS（`internal/panel/web`），无构建、无依赖。

**Spec:** `docs/superpowers/specs/2026-11-17-im-motion-design.md`

## Global Constraints

- 只改 `.chat-app` 下的样式和 `views/chats.js`、`views/chat.js`（及 `views/avatar.js` 如需要）；`.chat-classic` 和其他页面一个像素都不变。
- 时长 150–250ms（"正在输入"的点循环约 1.2s）；缓动 `ease-out` 或 `cubic-bezier(.2,.8,.2,1)`。
- `@media (prefers-reduced-motion: reduce)` 下 `.chat-app` 内所有动画和过渡关闭；"正在输入"的点静止可见。
- 首次加载的历史消息不加动画；只有轮询新到的消息和自己刚发出的消息加。
- 不加依赖；公开仓库只用假数据；提交说明英文 conventional。
- 现有行为不能变：轮询、滚动到底、建议回复、未读、菜单开关、窄屏切换、列表"无变化不重绘"。

## Review Focus

1. 列表每 5 秒轮询——期望角标只在数字变化时弹一次，不会每轮都弹；静态检查 + 假 DOM 自测。
2. 打开一个有 50 条历史的聊天——期望没有一屏消息同时飘入；假 DOM 自测。
3. 自己发一条消息后轮询又带回同一条——期望只动一次（按 seq 或 id 去重）；假 DOM 自测。
4. 系统开启"减少动态效果"——期望没有动画、"正在输入"的点仍可见；静态检查 CSS 媒体查询。
5. "正在输入"出现/消失——期望顶栏高度不变、不跳动；无头浏览器测量。
