# 技能（Skill）

技能让模型在直接对话里调用内置工具，比如记住一件事、查以前的聊天记录、看现在几点。每个技能是一个 `SKILL.md` 文件：开头写元数据，正文写给模型看的用法说明；每个技能用到一个或多个内置工具。设计见 [`superpowers/specs/2026-11-13-skills-design.md`](superpowers/specs/2026-11-13-skills-design.md)。

## 什么时候用得上工具

- 只有机器人在 `bots[].skills` 里启用了技能才会用。省略或为空时请求里不带任何工具，行为和没有技能框架时完全一样。
- 只在**私聊**和**群里的直接对话**（@ 机器人、回复机器人的消息）里用。在聊轮次、主动加入群聊、会话外提问都不带工具。
- 技能的 `conversations` 决定它在哪类会话里生效：只写 `private` 的技能在群里不出现。

## 技能文件格式

```markdown
---
name: memory
description: 记住用户要求记住的事、回忆以前聊过的内容、查询好感度
tools: [remember, recall, get_affinity]
conversations: [private, group]
---
（给模型看的用法说明，不超过 600 字）
```

| 字段 | 要求 |
|---|---|
| `name` | 1–32 个小写字母、数字、`-`、`_`，必须和所在目录名相同 |
| `description` | 一句话说明，不能为空（给人看，不进 prompt） |
| `tools` | 用到的工具名，至少一个，不能重复；v1 只能是内置工具 |
| `conversations` | `private`、`group` 中的一个或两个 |
| 正文 | 去掉首尾空白后不能为空，最多 600 字（按字符计） |

frontmatter 不认识的字段会被拒绝。文件可以带 UTF-8 BOM，换行可以是 CRLF。

## 内置技能

内置技能打包在二进制里（`internal/skills/builtin/<name>/SKILL.md`）：

| 技能 | 工具 | 会话 |
|---|---|---|
| `memory` | `remember`（记住说话人的一件事）、`recall`（在本会话的聊天记录里查）、`get_affinity`（查说话人的好感度） | 私聊、群 |
| `time` | `now`（按 `server.timezone` 取当前日期和时间） | 私聊、群 |

## 新增或覆盖技能

1. 在配置里写 `skills.dir`（相对路径按配置文件所在目录解析）：

   ```yaml
   skills:
     dir: ./skills
   ```

2. 在目录里为每个技能建一个子目录，放一个 `SKILL.md`：
   - 子目录名和某个内置技能相同（如 `skills/time/SKILL.md`）时，替换那个内置技能，常用来改写用法说明；
   - 名字不同时，作为新技能加入。

   以 `.` 开头的目录和目录里的普通文件会被忽略；子目录里没有 `SKILL.md` 算配置错误。

3. 在要用的机器人上启用（见下一节），重启 `conloom serve`。

v1 的技能只能组合内置工具，不能定义新的工具（HTTP 等外部工具留到以后）。

## 给机器人启用

```yaml
bots:
  - id: bot_tg
    skills: [memory, time]
```

列表里的名字不能为空或重复。按列表顺序，适用于当前会话类型的技能正文会接在 system 末尾：

```text
【技能】你可以在需要时调用下面的工具；不需要时直接回复。
<memory 的正文>
<time 的正文>
```

对同一个机器人、同一类会话，这一段是固定的，不影响 system 前缀的缓存。

## 启动校验

`conloom serve` 启动时加载内置技能和 `skills.dir`，并检查每个机器人启用的技能。下面任何一种情况都按配置错误处理，退出码 78：

- 技能文件格式不对（frontmatter 缺失或不完整、取值不合法、正文超长），即使没有机器人启用它；
- `skills.dir` 不存在，或某个子目录里没有 `SKILL.md`；
- 机器人启用了不存在的技能，或者启用的技能用到了没有注册的工具。

工具只在被启用的技能引用时才检查：没有机器人启用的技能，即使引用的工具不存在也不报错。

## 一次回复里的工具调用

1. 带着工具定义调用模型。工具定义和技能段都计入 token 估算。
2. 模型返回工具调用时，按顺序执行，每轮最多 4 个，多出的直接回复“本轮调用太多。”。带工具调用的 assistant 消息和每个调用的结果作为 tool 消息追加到对话里，再调用一次。
3. 最多 3 轮。第 3 轮之后的那次请求设 `tool_choice: none`，要求模型直接给出文字；如果它仍然要调用工具，就用它同时给出的文字，没有文字则按模型输出为空处理。
4. 不认识的工具名、参数不是 JSON 对象、工具报错时，结果写“调用失败。”，不带任何细节，对话照常进行。空参数按 `{}` 处理。
5. 单个工具结果最多 2000 字，多出的截掉。每个调用最多执行 10 秒。
6. 每次请求都重新申请准入；一次回复里用同一个模型配置。调用失败时按原有逻辑换一个模型重来一次，已经执行过的同名同参数调用直接复用结果，不会重复执行。
7. 只有最终的文字回复会发出去，并照常经过 `[[SKIP]]`、清洗记录格式和输出审查；中间轮次模型给出的文字不发送。

## 安全边界

- 工具只能通过调用上下文（`skills.Invocation`）知道“是谁、在哪个会话”：永远是当前这条消息的说话人和会话。参数里没有任何用户 ID 或会话 ID，模型不能替别人做事。
- 工具结果只回给模型，不直接发到群里；工具出错只告诉模型“调用失败。”，错误细节不进 prompt 也不进回复。
- 删除数据、改设置这类操作（`/忘记我`、`/persona use`、`/pause` 等）不做成工具，只能用命令。
- 技能用法说明要求模型不在回复里提到工具、系统或查询过程。

## 观测

- 指标 `conloom_skill_calls_total{tool, result}`，`result` 为 `ok`、`error`（工具报错）、`unknown`（不认识的工具，`tool` 记为 `unknown`）、`invalid`（参数不是 JSON 对象）。复用的结果和“本轮调用太多”不计入。
- 每次执行打一条 Info 日志 `skill call`，带 `task_id`、`tool`、`duration_ms`、`ok`、`result`；**不记录参数和结果的内容**。
- 带工具的请求，`model call` 日志多出 `round` 和 `tool_calls`；任务结束的 `task finished` 日志带 `skill_calls`（如 `now:1,remember:1`）。
