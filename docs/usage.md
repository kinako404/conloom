# 使用指南

本文介绍怎么运行 ConLoom、在群里能用哪些命令，以及机器人在群里什么时候说话、什么时候不说话。配置字段见 [配置参考](configuration.md)，内部实现和各项上限的推导见 [架构](architecture.md)。

## 命令行

所有功能都在一个二进制 `conloom` 里：

```text
conloom serve -c conloom.yaml                                   核心服务（API、判定、调度、模型调用、发件箱）
conloom adapter napcat -c conloom.yaml                          NapCat 适配器（独立进程，可以部署在别的机器上）
conloom mock -c conloom.yaml [-conv <类型>:<ID>] [-user <ID>:<昵称>]   终端里的 Mock 适配器
conloom backup -c conloom.yaml -o <文件>                         在线备份数据库（目标文件必须不存在）
conloom version                                                 显示版本与提交
```

- `-c` 默认为 `conloom.yaml`。
- 退出码：0 正常，1 运行时错误，2 参数或配置错误。
- 收到 SIGINT / SIGTERM 时优雅退出；关闭过程中再收到一次信号会直接结束进程。

**Mock 适配器**只通过公开 API 和核心交互，用来在本地体验和调试：

- 不带参数时，以配置里该机器人的第一个管理员身份私聊（机器人没有管理员时必须传 `-user`）。
- `-conv group:10001` 模拟群聊，`-conv private:20001` 模拟和某人的私聊。
- `-user 20001:小明` 指定发送者，省略昵称时用 ID 代替。
- 每行输入一条消息；在群聊里以 `@` 开头表示 @ 机器人。读到输入结束（Ctrl+D，Windows 为 Ctrl+Z 回车）时退出。
- Mock 和 NapCat 适配器默认使用同一个机器人实例，会争抢同一个发件箱。每个机器人实例只能运行一个适配器进程，不要同时运行两者。

## 聊天命令

| 命令 | 权限 | 作用 |
|---|---|---|
| `/help` | 所有人 | 简短说明 |
| `/stop` | 发起者或管理员 | 取消本会话正在进行或排队的回复；非管理员只能取消自己发起的 |
| `/persona` | 所有人 | 显示当前人格名称与版本，人格设置了角色名时一并显示 |
| `/persona list` | 管理员 | 列出配置里可用的人设模板名 |
| `/persona use <模板名>` | 管理员 | 把该模板复制成本群的新人格版本（原因记为 `command`），立即生效 |
| `/pause` | 管理员 | 暂停本群回复（群并发设为 0），静默取消本群正在生成或排队的回复，清空在聊会话和停顿计时器；暂停期间也不会主动加入群聊 |
| `/resume` | 管理员 | 恢复回复：群并发恢复为暂停前最近一个非 0 的值（找不到时用默认值，仍为 0 时用 1） |
| `/主动`、`/proactive` | 所有人 | 查看自己的主动搭话档位、是否有资格、今天已被主动搭话的次数 |
| `/主动 关`／`低`／`中`／`高`，`/proactive off`／`low`／`mid`／`high` | `eligibility_ttl` 内 @ 过或回复过机器人的人 | 设置自己的主动搭话档位（中英文等价），任意档位都可以设，包括从“关”重新打开 |
| `/主动 全群 开`／`关`，`/proactive group on`／`off` | 管理员 | 本群主动搭话总开关（生成新的群策略版本） |

命令前缀默认为 `/`（群策略 `reply.command_prefix`）。管理员只认配置里 `bots[].admins` 列出的平台用户 ID。命令不调用模型。

- 非管理员的命令和普通回复共用每用户限流（`reply.user_rate_limit_per_minute`），超出后命令只落库、不回应（`suppressed_reason` 为 `rate_limited`）；群暂停期间非管理员的命令同样不回应（`paused`）。管理员的命令（包括 `/pause`、`/resume`、`/stop`）不受限流和暂停影响。
- 通过 `/pause` 或 `PUT /api/v1/conversations/{id}/policy` 把群并发设为 0 时，正在生成和排队的回复都会被静默取消（不发“已停止”提示），`/resume` 之后不会补发暂停前积压的回复。
- 事件发生时间（`occurred_at`）距今已超过 `runtime.stale_task_after`（默认 2 分钟）的需要回复的消息（@ 机器人、回复机器人、私聊、命令、在聊轮次）只落库、不回复，`suppressed_reason` 为 `stale`。例如核心停机期间 NapCat 适配器缓存的消息，在核心恢复后才提交时就这样处理，不会在恢复后集中回复一批旧消息。消息时间来自平台（NapCat 所在机器的时钟），所以 NapCat 和核心所在机器的时钟要保持同步（如启用 NTP）；如果 NapCat 的时钟比核心慢超过这个阈值，所有消息都会被当作过时而不回复。
- 非管理员使用 `/persona list`、`/persona use` 时回复“只有管理员可以这样做。”，不会生效；`/persona` 后跟其他内容时回复用法。模板名不存在时回复可用的模板名，不写入新版本。
- `/主动` 系列命令只在群聊里使用，私聊中回复“主动搭话只在群聊里使用。”。还没有资格的人设置档位时回复“先 @ 我聊几句，才能开启主动搭话。”；非管理员使用 `全群` / `group` 子命令时回复“只有管理员可以这样做。”，不会生效；参数不对时回复用法。

## 机器人在群里怎么说话

目标是不乱插话、不句句都回，但在合适的时机主动加入群聊。以下行为只在群聊中生效，机器人在群里有三种参与方式：

1. **直接对话**：@ 机器人、回复机器人的消息、命令（以及私聊），每次都回复（仍受限流、暂停和过时检查约束）。
2. **在聊模式**：机器人正在和某些人聊时，这些人不 @ 机器人的后续发言按“轮”处理，由模型判断这一轮值不值得回应，可以不回。
3. **观望模式**：机器人没在聊时，只有群里的对话出现自然停顿，且资格、相关性和预算都满足，才让模型看最近的对话，决定要不要加入一两句。

后两种都遵循“规则先筛、模型兜底”：便宜的规则判定在前，只有通过筛选才调用模型，模型仍可以拒绝发言。

**跳过标记**：在聊模式的每一轮和加入群聊的任务，会在当前消息末尾附加一段固定提示，告诉模型没有人 @ 它、不需要每句都回应，不合适就只输出内部跳过标记 `[[SKIP]]`。模型输出（去掉思考段后）只要在任何位置含有这个标记（忽略大小写、空白和零宽字符，全角括号与【】视同方括号），或整条输出只是 `SKIP` / `[SKIP]`（允许前后带标点），整条输出都会被丢弃：不产生任何动作，也不进入发件箱，标记永远不会出现在群里。这类任务的状态仍是 `succeeded`，`meta.review_result` 为 `skipped`。

**回复格式**：群里的回复默认直接发出，不使用 QQ 的引用回复，只在可能弄不清是在回应谁时才引用它回应的那条消息（任务的最后一条触发消息）。由群策略 `reply.quote` 控制：

- `auto`（默认）：满足任一条件才引用——触发消息之后已有其他群友发言（触发者本人的补充和机器人自己的消息不算），触发消息已超过 60 秒，或它已不在最近 20 条消息里；查询策略或近期消息失败时也按引用处理。直接对话、命令、在聊轮次和加入群聊都按这条规则。
- `always`：总是引用。
- `never`：从不引用。

私聊从不引用。

### 在聊模式

群策略 `reply.continuation_window` 是在聊会话的保持时间（0~10m；0 表示不开启在聊模式，只回直接对话；示例配置为 `0s`）。每个群同时最多有一个在聊会话，只记在内存里，重启后清空（最多让一段闲聊需要重新 @ 机器人）。

- **开始与刷新**：机器人回复了群里 @ 它或回复它的消息后，发起者成为在聊会话的参与者（会话不存在时随之开始）；会话中的直接对话同样把发起者加入，并把下面的未点名回复和连续跳过计数清零。直接对话被模型跳过或被审查拦截、没有真正发出回复时，不加入会话。机器人以加入群聊的方式发言后（见[观望模式](#观望模式)），也会开始一段会话，参与者是当时最近对话中的全部目标资格人，并且已计 1 次未点名回复。
- **轮次**：参与者不 @ 机器人的发言触发一轮（任务 `trigger` 为 `continuation`）。机器人等他停顿 `turn_gap`（默认 6 秒）再处理；他一直在说时，从这一轮第一句算起最多等 `turn_max_wait`（默认 20 秒）。同一人在这期间的几句话合并为一轮，只处理一次（调用一次模型，失败时换一个模型重试一次），回复针对他最后一句。模型被告知不需要每句都回应：只有对方在问它、在等它回应，或者它有明显值得说的话时才回复一两句（单纯附和，比如“确实”“是啊”“哈哈”，不算值得说的话）；对方在和别人说话、话题已经转开或没必要回应时输出跳过标记。
- **接话冷却**：机器人在本群说过话（任何方式）后的 `turn_cooldown`（默认 45 秒）内，以及本群有任务正在运行时，未点名的一轮先挂起，不调用模型；日志记一条 `turn deferred`（因冷却挂起时为 `waiting_for=cooldown` 并带 `until`，冷却已过、只在等运行中的任务时为 `waiting_for=running`）。
  - 挂起期间他的后续发言都并入这一轮，每并入一句就重新等他停顿 `turn_gap`（不受 `turn_max_wait` 限制，也不会另开一轮）。冷却已过、本群没有任务在运行、他已停顿满 `turn_gap`、并满足最短回复间隔时才处理，模型看到他这段时间说的全部内容。
  - 一轮最多挂起 `turn_cooldown + turn_max_wait`（默认 65 秒，从这一轮第一句算起）。到点后合并窗口关闭，他的新消息另开一轮；此时冷却已过且没有任务在运行就立即处理，否则丢弃这一轮（不调用模型、不计入连续跳过，日志 `turn dropped reason=held_too_long`）。
  - 挂起的一轮不挡别人：其他人的 @、回复、命令、加入群聊和会话外提问照常及时处理。他在挂起期间 @ 或回复了机器人，就按直接对话及时回复（只回一条）。被点名的回复、命令和加入群聊不受接话冷却影响。
  - **明确提问不受冷却限制**：这一轮里只要有他自己发的明确提问（判定同[会话外提问](#观望模式)：含问号、以“吗”结尾，或含“怎么”“为什么”等疑问词），无论是开新一轮时还是挂起期间并入的，这一轮就不再等冷却，也不会到上限被丢弃。它仍是普通的一轮：照常等他停顿 `turn_gap`、本群有任务在运行时等它结束、计入未点名回复和连续跳过的计数，模型仍可以选择不回。
- **规则退出（不调用模型）**：参与者的非 @ 消息如果 @ 了机器人以外的人（包括 @全体成员），或回复的是另一位群友的消息，就不回复、只落库，并把此人移出参与者；参与者都走了，会话结束。
- **非参与者**：不在会话里的人不 @ 机器人的发言只落库（会进入上下文），不触发回复。
- **结束**：满足任一条件会话即结束——连续 `max_consecutive_skips`（默认 2）轮都没回（模型输出跳过标记、输出只剩聊天记录格式、被输出审查拦截或调用失败；在聊轮次和加入群聊的任务失败时不发错误提示）；自上次被直接点名以来，未点名的回复达到 `max_unprompted_replies`（默认 4）次；超过 `continuation_window` 既没有参与者发言也没有机器人回复；参与者全部规则退出。`/pause` 也会清空会话。
- `continuation_window` 不为 0 时必须大于 `turn_cooldown`，否则配置或策略校验失败。即便如此，保持时间短于 `turn_cooldown + turn_max_wait` 时，挂起很久的一轮放行时会话可能已经超时，这一轮仍会被丢弃。

会话结束后，之前的参与者不 @ 机器人的消息只落库；要等他再 @ 机器人或回复机器人的消息并得到回复（或机器人加入群聊时他作为目标资格人在场），才会再次成为参与者。由于观望模式要求机器人上次发言后至少过 `join_cooldown`，会话刚结束时机器人也不会马上以加入群聊的方式回来。会话轮次中的消息会更新发言者的兴趣画像，但不刷新资格。

### 观望模式

- **时机**：每条落库的群消息（包括命令和 @ 机器人的消息）都会重置该群的停顿计时器（`proactive.join_lull`，默认 15 秒）。群里安静满这个时长算一次“停顿”，此时做一次加入评估检查；新消息到来会取消还没到点的计时器，所以大家聊得正热时不会插话。停顿检查本身不调用模型。
- **条件**（全部满足才调用模型）：
  1. 本群主动搭话总开关打开（`proactive.enabled`），群未暂停；
  2. 当前没有在聊会话，本群也没有排队或运行中的任务（被接话冷却挂起的轮次不算）；
  3. 机器人上一次在本群发言（任何方式）距今至少 `join_cooldown`（默认 10 分钟）。这个时间记在内存里，重启后第一次检查时从库里本群最近的机器人消息恢复，所以重启不会让机器人立刻加入；
  4. 最近 `join_window`（默认 5 分钟）内至少有 `join_min_messages`（默认 4）条非机器人、非命令的消息，且最后一条没有过时（`runtime.stale_task_after`）。例外是没人接的提问：最新一条消息是目标资格人提的明确问题（含问号、以“吗”结尾，或含“怎么”“为什么”“为啥”“有没有”“谁知道”“是不是”“能不能”“会不会”“要不要”“哪个”“哪里”“多少”，比第 6 条的判定更严），且它本身可以作为下面的目标消息时，一条也够；
  5. 窗口内至少有一位发过言的**目标资格人**：有资格、档位不是“关”、今天被主动搭话的次数未达档位上限、距上次被主动搭话至少 `user_cooldown`；
  6. 相关：窗口内的文本和某位目标资格人的兴趣画像按其档位匹配，**或者**窗口里有人提问（含“？”或“?”，以“吗”“呢”“么”结尾，或含“怎么”“为什么”“为啥”“有没有”“谁知道”“啥”“咋”）；
  7. 预算：本群最近一小时的加入评估少于 `join_evaluations_per_hour` 次（默认 4），且最近一小时的主动发言少于 `group_hourly_limit` 次（默认 4）。
- **会话外提问**：只在机器人正在和别人聊（有在聊会话）时适用。如果最新一条消息是会话外一位目标资格人提出、没人接的明确问题（判定同第 4 条的例外，且它本身可以作为目标消息），停顿后仍会只针对他调用一次模型回答（日志带 `guest=true`），不受冷却限制，第 7 条的预算照常适用；回答后他加入当前的在聊会话。没有在聊会话时（包括会话刚结束），冷却照常生效。
- **目标消息**：窗口内最新的一条由目标资格人发出、不是命令、没有 @ 任何人、也没有回复别的消息（回复其他群友、回复机器人、回复库里找不到的消息都不行；@ 机器人和回复机器人的消息已经直接回复过）。没有这样的消息就不加入。
- **发出**：通过检查后记一次评估，建一个 `trigger` 为 `proactive` 的任务（触发消息为目标消息），等待模型准入时排在普通回复之后。模型看到最近的对话，被告知没有人 @ 它、只有能自然接上正在聊的话题、对大家有帮助或有趣、而且不会打断别人时才说一两句，并会知道目标资格人以前常和它聊的话题（合并后的前 5 个兴趣词）。提示的措辞随目标消息发送者的档位变化：“低”最保守，不合适就跳过；“中”在能自然接上话题时插一句；“高”会告诉模型对方很欢迎它多参与，可以像群友一样接梗、回应，只有大家在谈正事或实在没话说时才跳过。调用模型前和发出前都会重新检查总开关、暂停、目标人的档位和发言上限，已不满足就按跳过处理（不调用模型或不发送）。模型决定加入时，回复针对目标消息发出（是否引用按 `reply.quote`；目标消息之后通常已有别人发言，所以默认多半会引用），随后开始一段在聊会话；模型输出跳过标记则不发送。

每次停顿检查没有加入时，日志记一条 `join skipped` 并带原因代码，各代码的含义见 [架构 4.4 节](architecture.md#44-观望加入)。

### 资格、档位与上限

- **资格**：在本群 @ 过机器人或回复过机器人的消息（只发命令不算；在聊会话中不 @ 的消息只更新兴趣画像，不刷新资格）。超过 `eligibility_ttl`（默认 30 天）没有再这样做，资格失效。有资格的人可以用 `/主动` 设置任意档位，包括把“关”重新打开；但只有有资格且档位不是“关”的人才算目标资格人。从没 @ 过机器人的人永远不是目标资格人：如果群里聊天的都是这样的人，停顿再多次也不会调用模型。
- **档位**：`关` / `低` / `中` / `高`（`off` / `low` / `mid` / `high`）。首次获得资格时为 `default_level`（默认“低”）；没自己设过档位的人每次 @ 机器人或回复机器人时跟随群当前的 `default_level`；用 `/主动` 自己设过的档位之后一直保留，不会被默认值覆盖。
- **兴趣话题**：核心从每人 @ 机器人、回复机器人以及在聊轮次的消息里提取关键词（英文单词和连续汉字的二字词组，去掉常见虚词和口头禅），形成带衰减的兴趣画像，每人最多保留 50 个词。观望模式中，最近对话的文本和某人的画像足够重合才算“聊到了他常聊的话题”：低档需与前 20 个词至少重合 2 个，中档与前 30 个词至少重合 1 个，高档与前 50 个词至少重合 1 个。
- **发言上限**：每人每天最多被主动搭话 低 2 次、中 4 次、高 8 次（`daily_limits`）；对同一人两次主动搭话至少间隔 `user_cooldown`（默认 30 分钟）；全群每小时最多主动发言 `group_hourly_limit` 次（默认 4）。
- **“每天”的界定**：按 `server.timezone`（默认 `Asia/Shanghai`）的自然日计数，从当地 00:00 开始，到下一个当地午夜清零。
- **计数持久化**：评估和发出的记录存在数据库里，按时间窗口计数，重启后依然有效；7 天前的记录会被定期清理。
- **总开关**：管理员用 `/主动 全群 开` / `关`（只改 `proactive.enabled`，其余设置不变），或通过群策略 API 写入完整的 `proactive` 段（见 [API](api.md#群策略)）；`/pause` 期间同样不会主动加入群聊。总开关只管观望模式，在聊模式由 `reply.continuation_window` 决定。

### 模型调用的上限

以下按“处理次数”计：每次处理调用一次模型，调用失败时会换一个模型重试一次，所以一次处理最多发出两次模型请求。

- **直接对话**：每次触发（合并后）只处理一次，受每用户限流约束。
- **在聊模式**：每轮只处理一次，对方连发几句也只算一轮；两次未点名回复之间至少隔 `turn_cooldown`（含明确提问的一轮除外，最短只隔 `turn_gap`）。两次被直接点名之间，一段会话最多有 `max_unprompted_replies` 次未点名回复，两次回复之间最多连续跳过 `max_consecutive_skips − 1` 轮（再多一轮会话就结束），所以最多处理 `max_unprompted_replies × max_consecutive_skips` 轮（默认 4 × 2 = 8 轮），之后必须重新 @ 机器人。
- **观望模式**：每群每小时最多 `join_evaluations_per_hour` 次加入评估（默认 4），与群消息数量无关；有人刷屏时，停顿只会更少。

## 人设模板

每个群（会话）有自己的人格，带版本。人格由内置的核心规则和群人设组成：核心规则始终排在人设之前，人设不能改变它们（例如被认真问到是不是 AI 时会如实承认）。

- **初始人格**：会话第一次用到人格时，按 `bots[].persona_template` 复制配置里的模板，生成第 1 版；之后以库里的最新版本为准。修改配置里的模板不会影响已有会话。
- **应用模板**：管理员在群里发 `/persona list` 查看可用模板，`/persona use <模板名>` 应用到本群；也可以通过 API `PUT /api/v1/conversations/{id}/persona` 写入 `{"template":"<模板名>"}`。两种方式都生成一个新版本，记下模板名并写审计，立即生效。
- **修改与回滚**：API 也可以写入完整人格，或用 `rollback_to` 回到某个旧版本（回滚等于用旧版本的内容新建一个版本），见 [API](api.md#人格)。
- **角色名**：人设设置了 `character_name` 时，它就是机器人在这个群里的名字：system prompt 的“你是{名字}”、上下文里的“你（名字）”、回复的回声清洗和 `/help` 都改用它；不设时用 `bots[].name`。
- **写一个模板**：除了风格数值和行为偏好，还可以写角色设定、说话方式和示例对话，字段和字数限制见 [配置参考：人设模板](configuration.md#人设模板)。示例配置里有一个原创角色模板 `librarian` 可以参考。
